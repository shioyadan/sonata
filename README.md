# Sonata

**[▶ ライブデモ](https://shioyadan.github.io/sonata/#demo=rename-rush)**

**プロセッサの実行トレースを、動きで見る。**

Sonata（そなた）は、プロセッサ内部を流れる命令を WebGL で可視化するブラウザアプリです。命令列、依存行列、レジスタリネーム、物理レジスタ、実行パイプ、ROB、コミット、予測ミスからの復帰を、実トレースに沿って再生します。

LOAD と STORE は別のパイプで表示します。ロードは観測した最短アクセス時間に合わせた長さで通過し、遅い応答の超過分は LOAD WAIT で待機します。ストアは管路を通過したらROBで待機し、記録に再実行があればその時刻に読み出し・実行へ戻ります。コミット後の書込み状況は命令の詳細に表示します。[表示と記録の対応](docs/visualization.md)を参照してください。

スケジューラは全命令で共通です。整数・分岐は **INT / BR**、FP・SIMDは **FP / SIMD** の実行ユニットへ進みます。FP・SIMD命令は青色、分岐は紫色で識別し、FP用のロード・ストアはメモリ側に残します。命令名・オペランドによる表示上の分類であり、実機のユニット構成や容量を示すものではありません。

フロントエンドでは、同じサイクルにFetchされた命令を一列の束にして並べます。束の中はプログラム順、古い束は出口側に置き、各命令が次段へ進む時刻は記録どおりに保ちます。Fは4束分の表示枠に固定し、入り切らない命令は入力側の文字帯で表示を待たせます。次段へ進む記録時刻で枠を空け、後続を入れるため、待機束が増えてもFの幅は変わりません。

## 起動

ソースからビルドする場合はNode.js **22.23.2 以降**を使用します。推奨バージョンは `.nvmrc` に記録しています。ビルドと `npm start` には Node の標準ライブラリだけを使うので、依存パッケージのインストールは不要です。

```sh
git clone https://github.com/shioyadan/sonata.git
cd sonata
npm run build
```

生成された **`dist/sonata.html`** をブラウザで開いてください。コード・スタイル・解析器・ライセンスを含む単一 HTML です。別の場所へコピーしても、手元のトレースをネットワーク接続なしで開けます。ブラウザは WebGL 2 が必要です。

サンプルを試す場合は `npm start` で `http://127.0.0.1:4173` を開き、一覧から選んでください。6つのデモは `dist/samples/` の5本のgzip生トレースを使い、選択時に必要なファイルだけを取得・解析します。`#demo=rename-rush` のようなリンクで直接開くこともできます。ソース変更後はサーバーを再起動してください。

サンプルも手元のファイルも、同じWorker・Konata core・区間変換を通して読み込みます。サンプルの名前・初期位置・見どころ・出典は小さな一覧にまとめ、命令やレジスタ値は生ログから解析します。

通常の起動時はトレース未選択です。HTMLを直接開く `file://` ではサンプルの通信を行わず、手元のファイルを開く案内を表示します。

### 起動ヘルパーと更新

Linux・macOS・WSLでは、BashとPython **3.9以降**で起動ヘルパーを使えます。起動・配信・更新の処理は `sonata.sh` 1本にまとまっています。上の手順でビルドするか、[配布ZIP](https://shioyadan.github.io/sonata/sonata-latest.zip)を展開して、そのディレクトリで実行してください。ZIP版の起動・更新にはNodeやnpmは不要です。

```sh
./sonata.sh /path/to/trace.log.zst
# トレースを指定せず、サンプル一覧から開く場合
./sonata.sh
# ポートを固定する場合
SONATA_PORT=8080 ./sonata.sh /path/to/trace.log.gz
```

空きポートでWebサーバーを起動し、開くURLと `ssh -L ...` の転送コマンドを表示します。SSH先で起動した場合は、表示された転送を手元で設定してURLを開いてください。待ち受けは `127.0.0.1` に限定し、本体・同梱サンプル・明示した1本のトレースだけを配信します。指定トレースはブラウザで自動的に読み込み、gzip・zstdもWorkerで逐次解析します。サーバーは **Ctrl+C** で停止します。ブラウザを再読込みするとトレースも読み直します。

展開したZIP版は次のコマンドで更新できます。

```sh
./sonata.sh --update
```

現在と配布先のコミット・日付、変更されるファイルを表示し、確認後に更新します。同一内容なら変更せず、取得失敗・不正なZIPでは現在の配布物を保ちます。手元のトレースや無関係なファイルは更新対象にしません。更新後はヘルパーを起動し直してください。ソースのチェックアウトでは `--update` を使わず、Gitで更新して再ビルドしてください。固定名のZIPはmainのCI成功後、Pagesと一緒に更新されます。

## トレースを開く

**Open trace…** でローカルファイルを選択するか、画面へドラッグ＆ドロップしてください。Konata coreでKanata / Onikiriとgem5 O3PipeViewを判定し、非圧縮・gzip（`.gz`）・Zstandard（`.zst` / `.zstd`）を読み込みます。ファイルをサーバーへ送信せず、配布HTMLだけでオフライン動作します。

読み込みはバックグラウンドで進み、解析できた命令から表示・再生・区間移動できます。途中表示には後から命令が追加されるため、画面に読込み中と表示します。完了時も再生位置を保って最新の内容に更新します。**Cancel** で読み込みを取り消すと、最後に表示したサンプルへ戻ります。サンプルを開いていなければ未選択画面に戻ります。数GBのログでも全文の文字列や描画用の全命令配列を作らず、Konataの圧縮ページ保存を使います。

画面下部は二段の時間軸です。3Dに近い上段には表示区間の詳細と再生位置、下段の **PARSED TRACE**（狭い画面では **TRACE**）には読込み済みの全体活動と現在の表示区間を表示します。全体バーのクリック・ドラッグで遠くへ移動しても、再生中ならそのまま続き、停止中なら停止を保ちます。

詳細側の **Previous / Next**（**PageUp / PageDown**）は区間移動、ホイールまたは **− / +** は時間軸の拡大縮小、**Shift＋ドラッグ／ホイール** は区間の平行移動です。初期幅は128サイクル、拡大縮小は16〜512サイクルです。移動やズームの連打もまとめて反映します。詳細バーでの時刻指定と1サイクル送りは、観察のため再生を止めます。

再生と1サイクル送りは区間の境界を越えて続きます。次の区間を先読みし、読込みに追いついた場合は続きを待ち、ファイル末尾で停止します。速度は0.25〜32×から選べます。全体側の **Start / Latest** は先頭／読込済み末尾の区間へ移動します。**Go to cycle** にはサイクル番号、表示幅、スレッド、履歴の **Back / Forward**、**Bookmark**、明示的な **Loop window** をまとめています。デモは末尾でループします。

内容が確定した範囲では、命令が一つもない長い空白を自動で飛ばし、次の命令が現れる直前から通常再生します。**Go to cycle → Skip empty gaps** で切り替えられ、初期状態はONです。飛ばしたサイクル数を一時表示します。

命令がfetch段階・LOAD WAIT・ROBなどで待機し、状態が変わらない場合は、**Speed up waits**（初期ON）で選択速度の16倍に加速し、次の記録上の変化の手前で通常速度に戻します。コミット後のストア書込み待ちも対象です。加速中は **Fast-forwarding wait · 16×** と表示します。Kanataは読み込み中でも、未確定の命令がないと確認できた範囲から加速します。gem5は全体の読み込み完了後に加速します。待機の長さを通常速度で観察する場合はOFFにしてください。パイプ内の移動、完了・フラッシュの演出、未完了命令、**Loop window**、手動の1サイクル送りは加速しません。

右側の **Find in trace** からPC・命令文字列・命令ID、取消命令、一定以上の寿命を持つ命令を検索できます。選択スレッドの結果をID順に40件ずつ表示し、選ぶとその命令の時刻へ移動して停止します。寿命はfetchから最後の記録までの長さで、キャッシュミスや待機原因を表すものではありません。ブックマークには名前を付けられ、同じ名前・サイズ・更新時刻のファイルを再び開くと復元します。ファイル自体は保存しません。

ステージの構成は読み込んだ範囲からスレッドごとに蓄積します。役割はgem5・RSD・Onikiriの既知の記録規則、その他のログでは有界な命令標本の進行順から判定します。設定を確認できない容量は、標本と表示区間で観測した同時数から推定します。観察中の最大値と、重なる区間の命令位置を引き継ぎ、区間移動による配置の変化を抑えます。役割を判定できないステージは記録順の前段として表示し、未観測のレジスタ値や分類を補いません。ISAや物理レジスタの総容量は、デモの出典で確認した設定がある場合だけ適用します。未完了の命令はコミットさせません。同時に表示できる密度やFIFO順序には制約があり、対応できない区間は理由を表示します。大きなファイルも圧縮後の記録はメモリに保持するので、扱えるサイズは内容と端末の空きメモリに依存します。[読込みの構造と制約](docs/trace-import.md)を参照してください。

## 操作

| 操作 | 動作 |
| --- | --- |
| ドラッグ / 1本指 | カメラを回転 |
| 右ボタンドラッグ | 上へ動かすと拡大、下へ動かすと縮小 |
| ホイール / ピンチ | 拡大・縮小 |
| 2本指の平行移動 | 図を移動 |
| Fit / ダブルクリック | カメラをリセット |
| Neon / Aluminum / Paper | 発光・アルミ・紙模型の外観を切り替え |
| Space / ← → | 再生・停止 / 1サイクル移動 |
| PageUp / PageDown | ローカルトレースの前／次の区間 |
| F / C | 次のフラッシュ / Cinema |
| 命令の粒子・駒をクリック | 対象命令を追跡 |

スマートフォンでは再生・シークを画面内に保ち、**Demo & settings** からデモや表示設定を開きます。横向きにも対応しています。最初のサンプルは再生とアニメーションが自動で始まります。サンプル切替えでは再生・停止の状態を引き継ぎます。再生ボタンで一時停止し、**Motion effects** で演出を OFF にできます。

拡大は通常の Fit 表示から約10.8倍まで可能です。右ドラッグ・ホイール・ピンチ・ズームボタンで同じ上限まで近づけ、Fit で全体表示へ戻れます。

右上の Orbit / Top view / Cinema の下にある **Neon / Aluminum / Paper** ボタンで、発光する表示、アルミの表示、紙模型の表示を切り替えられます。視点ボタンと同じ見た目で1行に並び、スマートフォンでも図を見ながら操作できます。Aluminum は銀色の研磨面と幅のある反射、Paper は白い厚紙の積層・折り筋と、つやを抑えた紙面を表します。命令は Aluminum では色付き上面と銀色の縁を持つ金属パック、Paper では色紙を折った不透明な小さな折り箱です。初期表示は Neon です。[外観の仕様](docs/visual-styles.md)を参照してください。

Aluminum / Paper の命令は、待機・移動・実行を通して同じ大きさを保ちます。ユニット上では接地し、ステージ間は両端の高さを滑らかにつないで移動します。上面を上に保ったまま滑り、**Motion effects** の設定にかかわらず回転しません。命令の軌跡は、**Trails** が ON で命令を選択しているときに表示します。

## デモ

| デモ | シミュレータ / プロセッサ | 実行内容・見どころ |
| --- | --- | --- |
| Branch storm | gem5 ARM64 O3 | CoreMark、連続する予測ミス |
| Wide open | gem5 ARM64 O3 | CoreMark、高い命令流量 |
| Miss & recover | RSD / RISC-V | IntRegImm テストの起動処理、キャッシュミスと予測ミス |
| Rename rush | gem5 ARM64 O3 | CoreMark、記録されたリネームと物理レジスタの読み書き |
| x86 recovery | gem5 x86 O3 | CoreMark、micro-op とレジスタ復元 |
| NAMD flow | Onikiri2 / STRAIGHT ISA | SPEC CPUのNAMD、継続したディスパッチとFP演算、1回の予測ミスからの再開 |

実行条件は各デモの **Run details** と [デモの出自](data/README.md) に記載しています。データに記録された時刻・依存関係と、推定した構造や光の演出を区別しています。Top-down はトレースから推定した分類を、現在から過去8サイクルの窓で表示します。分類を支える構造や分岐回復の観測例が不足する場合は、その原因を断定しません。実装上の解釈は [可視化の仕様](docs/visualization.md) を参照してください。

## 開発と検証

```sh
npm ci
npm run format:check
npm run typecheck
npm test
npm run test:server
npm run test:render
```

TypeScript はブラウザ用コード全体の型検査用、Electron はブラウザの検証用です。配布 HTML には含みません。画面のない Linux では Xvfb を使用します。

```sh
xvfb-run -a -s '-screen 0 1600x1100x24' npm run test:render
# スマートフォンの表示・タッチ操作だけを検査
xvfb-run -a -s '-screen 0 1600x1100x24' npm run test:mobile
```

作業中は `npm test -- model playback` や `npm run test:render -- --sections=import-streaming` のように対象を絞れます。検査範囲の一覧・使い分けは[開発ガイドの検証](docs/development.md#検証)を参照してください。描画結果と経過時間は `artifacts/render-results.json` に保存します。

検証画像は `artifacts/screenshots/` に出力します。描画検査は、HTML単体のオフラインFile読込みと、ローカルHTTPでのサンプル取得・描画を確認します。検査用の本体とサンプル以外への通信は禁止します。通常のCIはモデル・ビルド・型検査と、`npm run test:smoke` による基本的な描画・操作の確認を行います。全描画検査はローカル、またはGitHub Actionsの手動実行で `full_render` を選んで行います。詳細は [開発ガイド](docs/development.md) にまとめています。

`npm run format` でソースと自作スクリプトを整形できます。README とソースコードの説明コメントは日本語で記述します。作業上の指針は [AGENTS.md](AGENTS.md)、継続して維持する判断と確認事項は [保守の資料](docs/maintenance.md) を参照してください。

## 構成

```text
src/                    編集用のソース
  sonata.cts            起動・操作・DOM 表示
  demo-loader.cts       サンプルの非同期取得・取消し・キャッシュ
  trace-import.cts      ファイル選択・進捗・区間要求・先読み
  trace-navigation.cts  全体時間軸・検索結果・履歴・ブックマーク
  trace-worker.cts      読込みWorkerの入口
  trace-file.cts        Konata store・区間索引・寿命
  trace-window.cts      選択区間を再生形式へ変換
  trace-structure.cts   スレッド別の構造観測と有界な標本
  trace-evidence.cts    詳細注釈・レジスタの逐次索引
  top-down.cts          選択区間のTop-down解析
  camera.cts            カメラ・投影・ポインター操作
  replay-model.cts      デモ準備・時刻に対応する再生状態
  geometry.cts          座標・経路・接地
  scene.cts             配置・固定部品・外観プリセット
  activity.cts          命令・待機列・レジスタ等の動的表示
  renderer.cts          GPU 資源・描画順
  shaders.cts           材質ごとの GLSL
  index.html            画面の骨格
  sonata.css            共通 UI・情報パネル
  scene.css             シーン上の表示
  appearance.css        画面サイズ対応・配色
data/                   gzip生トレース5本・デモ一覧・出典・CPU回帰用データ
scripts/                ビルド・検証・デモ抽出
sonata.sh               ローカル／SSH先で使う起動・更新ヘルパー
vendor/konata-core/      読込み・抽出に使う Konata core と生成済みブラウザ用コード
vendor/wasm-zstd/        同梱する圧縮器とライセンス
docs/                   可視化の仕様と開発手順
dist/sonata.html         オフラインでFileを開ける本体（Git 対象外）
dist/samples/            選択時に取得するgzip生トレース（Git 対象外）
artifacts/              検証画像・レポート（Git 対象外）
inputs/                 再抽出用の元ログ（Git 対象外）
work/                   ローカル作業メモ・引き継ぎ資料（Git 対象外）
```

ソースの分割と編集先は [構造の説明](docs/architecture.md) を参照してください。アプリ本体は単一 HTML に結合し、生トレースは別のgzipファイルとして配布します。通常のビルド・検証には Konata のチェックアウトや元ログは不要です。デモを再抽出する場合だけ、[再生成の手順](data/README.md#再生成) に沿って元ログを用意してください。
