# ローカルトレースの読込み

`Open trace…` とファイルのドロップで、Konataと同じKanata / Onikiri、gem5 O3PipeViewを読み込みます。Kanataの形式不一致だけをgem5へ渡し、壊れた圧縮データや読込みエラーを形式不一致として握りつぶしません。gzipとZstandardはストリーム展開します。URL入力やファイルのアップロードは行いません。

## 保存と表示の境界

- `src/trace-import.cts` はFile選択、進捗、取消、区間要求と先読みを所有します。
- `src/trace-navigation.cts` は全体時間軸、ズーム・移動操作、検索結果、履歴、ブックマークを所有します。
- `src/trace-worker.cts` は解析を継続しながら区間要求を受け付けるWorkerの入口です。区間要求は実行中1件と未実行の最新1件に制限し、新しい要求で古い取得を中断します。解析・検索とは独立して進めます。
- `src/trace-file.cts` はKonataの`parseTraceFile`を呼び、`ParsedTrace`と`PagedOpStore`の寿命、区間索引を所有します。
- `src/trace-structure.cts` は保存された命令からスレッド別の構造観測と有界なID標本を保持します。
- `src/trace-window.cts` は構造資料と有界な命令集合をSonataの再生形式へ変換します。ファイル・DOM・GPUには依存しません。
- `src/replay-model.cts` の`loadData`で準備が成功してから、描画側が保持する再生状態へ反映します。同梱デモの読込みも同じ入口を通ります。

FileをWorkerへ渡しても、ファイル全体を文字列やArrayBufferへ展開しません。Konataの圧縮ページ、展開ページのキャッシュ、命令キャッシュを使います。Zstdの入力展開とページ圧縮はさらに専用Workerで行います。画面へ返すのは進捗、ファイルの概要、選択・先読み区間のコンパクトな命令と有界な検索結果です。未完成の全命令を繰り返しコピーする処理はありません。

Coreの`onTrace`は途中でも同じstoreを公開します。`loaded`通知の`source.complete=false`は読込み中、`true`は全入力の解析完了を表します。最初に命令が保存されたら表示でき、その後の概要通知は最大4回/秒です。gem5はCoreの並べ替え用バッファが確定してから表示できるため、最初の行を読んだ直後に表示できるわけではありません。途中のページ容量は全ページ集計を避けて`null`とし、完了時だけ計測します。形式名は固定Coreのstream再開契約（1回目Kanata、形式不一致時だけ2回目gem5）と最終結果の一致を検査します。

読込み中も区間選択・再生を受け付けます。区間要求では対象ブロックのID集合とflush群を固定し、取得した命令だけを複製して解析側の更新から切り離します。初期表示は読込み済み範囲の伸長に合わせて選択幅まで広げ、その後は全体の進捗通知ごとに描画を再構築しません。完了時に現在の区間を再取得し、時刻と再生状態・残っている命令の選択を保持します。途中のstoreには未保存の命令があるため、画面は部分表示であることを明記します。

Parserが命令を保存する時点で、1024 IDごとの最小fetch時刻・最大終了時刻・実在IDのビット集合を索引化します。Coreの最初の`onTrace`で公開された`MutableOpStore.setOp`を観測し、保存処理自体は元の実装へ渡します。最初の公開前に命令が保存されていないことを検査し、Core更新で契約が変わった場合は失敗させます。Sonataの索引構築・区間選択では0から最大IDまで走査せず、疎なIDも扱えます。固定Coreのgem5パーサー内部にはID間隔の走査が残るため、形式を問わず間隔に依存しないという保証ではありません。区間変更では重なるブロックだけを展開します。fetch時刻だけで絞ると、左境界より前から続くロード待ちなどを失うため、生存区間の交差を確認します。区間の前6サイクル・後1サイクルも表示上の文脈として取得し、直前のcommit/squash演出と次のfetchを境界で消さないようにします。UIの区間時刻は広げず、含めた命令のステージ・終了時刻も切り詰めません。流入する命令文字列はさらに先の24行までをfetch順に取得し、ID・fetch時刻・短い名称・種別だけを渡します。将来のステージや完了結果は渡しません。ブロックの最小／最大fetchで絞り、最大65536命令の確認で先頭順序を確定できない場合は確定した行だけを使い、Run detailsに先読み制限を示します。各ブロックに長寿命命令がある場合は多くのブロックを再確認するため、検索時間が常に一定とは限りません。

圧縮済みページと索引もRAM上にあります。ディスク退避や無制限サイズの保証ではありません。新しいファイルを開くと前のファイルのstoreを閉じ、同梱デモへ戻ってから読み込みます。取消・デモ選択・ページ終了でもAbortSignalと`close`で解放し、応答がなくてもWorkerの終了期限を設けています。

## 区間と観測値

3Dに近い上段で表示区間を再生・シークし、下段の全体時間軸で読込み済み範囲から区間を選びます。区間の前後移動と拡大縮小は詳細軸の近くに置き、全体側の`Start / Latest`は先頭／読込済み末尾の区間へ移動します。`Latest`は表示幅を保って最後の区間の先頭から再生できる位置を選び、未読の時刻や末尾への自動追従を意味しません。初期幅は128サイクル、ホイールでは16〜512の整数幅へ拡大縮小し、`− / +`では倍率を半分・倍にします。ボタンのズームは現在時刻、ホイールは指している時刻を中心にします。Shift＋ホイール／ドラッグは区間を平行移動します。`Go to cycle`ではサイクル番号、16 / 32 / 64 / 128 / 256 / 512サイクル、スレッドを直接指定できます。複数スレッドは一つずつ3D表示します。

区間の前後移動はPageUp / PageDownでも行えます。移動・ズームの連打は最後に要求した位置を基準に積み重ね、応答が遅い場合も入力を取りこぼしません。再生速度は0.25〜32×（1〜128サイクル/秒）です。

全体軸をドラッグしている間は、その操作を始めた時点の読込み済み範囲と活動分布を固定します。選択枠とサイクル表示は入力へ即座に追従し、指を離してから区間を取得して、軸を最新の解析範囲に戻します。操作中の古い取得・先読みは取り消し、進捗や遅い応答で選択値を上書きしません。再生状態は保って時計だけを待機させます。タッチ操作の取消時も待機を解除し、必要なら保留していた完了時の区間更新を行います。

区間移動・拡大縮小・履歴による移動は再生状態を保ち、必要な区間を取得する間だけ時計を待機させます。応答を受け取っても再生状態を上書きせず、待機中の手動停止を尊重します。詳細軸の時刻指定、1サイクル送り、検索結果の選択は対象を観察するため停止します。

`Skip empty gaps`は初期ONで、内容が確定した範囲の自動再生に適用します。命令が一つもない空白が16サイクル以上残っている場合、0.35秒の通常再生後に空白の末端へ進みます。次fetchの2サイクル前と、完了・squashの後6サイクルは通常速度で見せます。表示幅を保って次の命令の直前の窓を直接取得するため、巨大な空白を窓ごとに再生する必要はありません。確認済みの空白がファイル末尾まで続く場合は末尾で停止します。短い窓の連続再生では0.35秒の猶予を引き継ぎます。

Kanataでは全入力のEOFを待たず、`source.settledCycle`より前だけを対象にできます。Coreの既存の未retire命令Mapから最古のfetchを読み、現在cycleとの小さい方を境界にします。未retire命令はstoreに未公開なので、最後に保存された命令の終了時刻だけでは安全性を判断できません。同じcycleの未読イベントも境界の外です。取得した窓に`playbackSafeUntil`を固定し、その2サイクル前で加速を止めます。後の進捗通知だけで古い窓の保証を広げず、窓全体が確定範囲へ入った時とEOFで再取得します。警告や逆行時刻のあるKanataと、並べ替え中のgem5はEOFまで加速しません。このCore変更の出典とハッシュは[vendorの記録](../vendor/konata-core/README.md)に保持します。

`replay-model.cts`の`createEmptyPlayback`は、命令の生存期間と記録イベントの前後をまとめ、空白区間を一度計算して二分探索します。長い待機は生存中、未完了は終端不明として保護します。窓外は確定した文字列先読みの最初のfetchまでに限り、先読みが尽きたことを確認できた場合は解析済み末尾までを`emptyTailUntil`に保持します。65536命令の走査上限で先頭を確定できなければ窓外を推測しません。集約histogramの空のbinを空白の証拠にはしません。

ストアの書込み待ちは`storeWaits`に`[id, fetch, retire, completion]`として渡します。命令本体が窓から外れた後も、選択区間と交差する待機だけを圧縮ページから取得します。既存の1024 IDブロックにstore IDのビット集合と待機範囲を追加し、全ストアの時刻配列を保持しません。tick/cycleの対応はファイル全体の記録から一定量の状態で校正し、不明なら補いません。表示窓には最大16384件とし、超えた場合は明示エラーにします。完了時刻は読込み済み末尾にも含めます。退役した命令を3Dに再登場させず、各書込み完了を独立した状態変化として扱います。手動・逆方向のシークでも同じ区間の待機を取得でき、過去に閲覧した窓には依存しません。

空白スキップは書込み待機の全期間を保護します。`Loop window`、OFF、手動シーク・停止は自動早送りより優先し、取り消した早送り応答で位置や再生状態を上書きしません。空白スキップ後は飛ばしたサイクル数を2秒表示し、記録のサイクル番号・レイテンシ値は変更しません。

`Speed up waits`も初期ONです。命令が存在していても、前段・scheduler・ROB・LOAD WAITなどで待機し、次の記録上の変化まで16サイクル以上残る区間を対象にします。コミット後のストア書込み待ちも含めます。`createWaitPlayback`へ表示準備済みの段を渡し、短いメモリ管路の通過と静止待機を区別します。元のfetch・stage開始/終了・allocation・issue・completion・retire/squash・依存のready・レジスタなどの記録イベントは別途、前2/後6サイクルを保護します。表示段をまとめてもMcや再発行の変化を失いません。0.35秒の猶予後に選択速度の16倍で連続的に進め、`Fast-forwarding wait · 16×`と明示します。待機の原因は推測せず、記録値や段の長さも変更しません。

待機加速は描画中も移動する`exec-*`と`register-read`の全期間、未知の段、段の欠落、未完了命令には適用しません。読み込みの確定範囲・ループ・手動操作の条件は空白スキップと共通です。加速分は現在の窓の末端で止め、次窓を適用してから判定し直します。短い窓の連続再生では猶予を持ち越し、加速で未取得窓のイベントを通り過ぎません。

再生末尾の35%手前から次の1区間を先読みします。区間間で境界の1サイクルを共有し、時間を飛ばさずに再生を続けます。先読みが間に合わなければ境界で待ち、読込み済み末尾に追いつけば解析の進行を待ちます。全ファイルの末尾では停止し、`Loop window`を選んだ場合だけ表示区間をループします。先読みできない区間では現在区間の末尾で理由を表示して止まり、対応できない命令を黙って除きません。カメラと区間内に残る命令の選択を保持し、1サイクル送りも境界を越えます。未完了命令は最後の観測ステージに保持し、コミットや未来のROB解放を追加しません。Kanataの`eof`だけでなく、gem5の`retired=false / flush=false`も未完了です。gem5 Coreの終端時刻が最後のretireまででも、記録されたステージの最大時刻を表示範囲に含めます。tick変換で負値になった未完了末尾のstage終端は、終了未観測として扱います。

gem5・RSDの既知のステージ名の組は形式に沿って役割を判定し、短い区間に順序逆転がなくてもスケジューラ・実行・ROBを前段に変えません。その他の名前ではKonataの構造検出をID昇順の有界なファイル標本に適用します。判定できない場合は名前と時刻を保った前段表示とし、観測した隣接順を使って並べます。架空のallocation / issue / completionは作りません。スレッド別に読込み済みのステージ名・隣接順・命令種別を蓄積し、表示区間からその構成が消えても維持します。構造標本と表示区間で観測したqueue / ROB容量、幅、実行パイプ数の最大値を保持し、表示を縮めません。この小さな配置キャッシュは最大32構成で、ファイルを閉じると破棄します。より密な区間や未知の前段構成に移れば配置が変わる場合があります。デモ抽出器のファイル名別のCPU設定やレジスタ数、固定tick倍率、特定ISAの依存推定は適用しません。レジスタ値・Top-downは未観測、依存関係はログにある辺だけを使います。

RSDのIs / Rrは読出し、X / Mt / Maはアクセス、Rwは待機・完了として区別し、再登場する段階も保ちます。LOAD / STOREの最短アクセスを同梱デモと同じ共有処理で求め、長いSTOREの待機をROBへ置きます。読出ステージがあっても値がなければ、その筐体だけを表示し、レジスタのセルや値は作りません。

LOAD / STOREの表示基準は、正常完了した最後のアクセスの最短時間を保持します。RSD / gem5は保存時の全体観測、その他の形式は役割を検出できた標本と表示区間から蓄積します。再試行、取消、未完了から短い基準を作らず、役割を判定できない場合もレイテンシを補完しません。既知のLOAD / STORE / atomicの経路は、その種別が現在の区間にいなくても保持します。

構造標本は1スレッド256 IDまで（先に保存された128件＋ID hashが小さい128件）、全スレッド合計4096 IDまでです。Opそのものは保持せず、資料の更新時だけstoreから読み、標本のステージ総数も65536までに制限します。資料が変わらなければ構造検出は再実行しません。容量は標本での下限を表示区間の観測で広げた値で、ハードウェアの仕様ではありません。構造観測は最大64スレッド、スレッドごとに128ステージ名・512隣接関係、名前は256文字までで、超過時は理由を表示します。

重なる区間を移動するときは、共有時刻のROBの位相、命令のスケジューラ・Rn・LOAD WAIT・実行レーンの位置を引き継ぎます。移動中の補間に必要な位置も予約します。予約が描画上限に収まらない種類だけ通常の割当に戻し、記録された命令や時刻を変更しません。前段構成が変わる場合や重ならない移動は新たに割り当てます。同じ配置・材質なら固定メッシュ・ラベル・静的な影を再利用し、待機状況の表示によってcanvasの高さを変えません。

gem5の`retire:0`は正確なsquash時刻を持たないため、連続する取消ID群の最後の観測終了時刻を表示上のsquash時刻と推定します。個々の生のstage・終了時刻とは別の`flushCycle`に保持します。群は全体索引にも保持し、生の終了時刻が区間開始より前でも群として生存中なら取得します。窓を移しただけで群の推定時刻が変わったり、ROBの途中だけを取り除こうとして表示できなくなることを防ぎます。

描画用の上限は`trace-window.cts`の`limits`にまとめています。命令・ステージ数、同時命令数、スケジューラ・ROBのセル数、同時経路数を確認し、黙って命令を減らさず、上限と対処を表示します。役割を検出しても単一FIFOとして表現できない区間では理由を表示します。短い区間を選ぶと総命令数を減らせますが、瞬間的な占有数そのものが大きい場合は区間を短くしても解決しません。

## 全体活動・検索・訪問位置

全体時間軸は全threadのfetch・commit・取消命令数を最大512binへ集約します。サイクル範囲が伸びると隣接binを併合し、全命令分の時刻配列は追加しません。1024 IDごとの実在・終了ビット集合で再書込みの重複計数を防ぎ、未完了をcommitへ含めません。全体軸は集約区間内の命令数、詳細軸は再生用のin-flight / commitで、共通の高さ尺度ではありません。

Kanataの終了時刻とgem5のRt開始を終了観測に使います。gem5の取消は正確な時刻が記録されないため、全体活動と検索では最後に記録されたstageの開始位置へ置きます。3Dのflush群に対する推定時刻とは区別し、凡例の説明に明示します。解析中は保存済みの命令だけを集計し、未読部分のサイクル長や活動を推測しません。全体軸も読込み済み範囲を表します。

検索はWorkerの圧縮storeを走査し、PCを含む名称・詳細ラベルの部分一致、命令IDの完全一致、取消、指定寿命以上の命令を扱います。文字検索は大文字小文字を区別しません。寿命検索はfetchから最後の記録までの長さで、未完了を除外し、待機原因は推定しません。選択threadの結果をID順に最大40件ずつ返し、`Find more`で続きを取得します。表示ラベルは1件2048文字、クエリは512文字までです。検索threadと部分結果であることを表示し、読込み中に後から追加された命令は再検索で反映します。

検索は短い間隔で制御を返して区間移動を妨げず、新しい検索とcloseで旧検索を取り消します。区間と検索の応答ID・エラー種別を照合し、古い応答で現在位置を上書きしません。手動シークで古い継続要求を無効にしても、EOF時の同一区間の更新は最新の再生位置を保って適用します。

区間取得には解析・検索と別のAbortControllerを使い、新しい区間要求や`cancel-window`で待ち列と実行中の古い取得だけを取り消します。命令・文字列先読み・検索の走査は経過時間を確認し、8msに達したらMessageChannelで制御を返します。命令数だけで過剰に中断すると、その都度Parserの処理が入り区間表示が遅くなるため、短い走査へ一律の待ちを挟みません。区間要求の実行開始前には一度taskへ戻し、解析中に溜まった移動先をまとめます。

履歴は同じファイル内の直近100訪問を保持します。ブックマークは名前、サイクル、表示幅、thread、選択命令IDを保存し、1ファイル50件・最近20ファイルまでブラウザのlocalStorageへ記録します。キーはファイル名・サイズ・更新時刻で、内容のハッシュ照合ではありません。元ファイルは保存せず、再起動後は利用者が選び直します。ブラウザが保存を拒否した場合はそのセッション内で使える旨を表示します。

## オフラインビルドと検査

KonataのTypeScript原本、固定リビジョン、ファイルハッシュは`vendor/konata-core/`に保持します。WASMを内包する圧縮器と各ライセンスは`vendor/wasm-zstd/`に固定します。開発時の`npm run core:generate`でTypeScriptを変換し、生成済み`browser.cjs`をコミットします。通常の`npm run build`はこれを使うため、Nodeの標準機能だけで完結します。ライセンス全文とWorker本文も配布HTMLへ含めます。

`scripts/check-import-drag.cts`では読込み途中の実Fileを使い、マウスで全体軸をドラッグしている間に古い応答とEOFを配送します。軸の固定・選択枠の追従・確定位置・区間末尾からの連続再生を検査し、実タッチ入力の取消と、その後のドラッグも確認します。ネイティブrangeは実入力で検査し、マウス移動には押下状態も渡します。

`scripts/check-empty-playback.cts`では窓内の空白、100万サイクルの空白と末尾、16サイクル窓の32倍速、OFF/ループ/手動操作、長い命令待ち、窓移動後のstore待ち、遅い早送り応答を実Fileで検査します。読み込み途中を空白と誤認しない検査は`check-import.cts`に含めます。

`scripts/check-wait-playback.cts`は111サイクルのfetch滞在を持つ小さなgem5入力を使い、静止待機の加速、次fetch前の通常速度への復帰、OFF/停止/ループ、小さい窓の継続と記録値の不変を確認します。まだfetchされていないstoreの遅い完了が、冒頭の加速を阻まないことも検査します。LOAD WAITの静止位置と応答前の減速、元命令が窓にない2件のstore完了・直接シーク・逆シーク・最後の完了までの再生も確認します。実ログや巨大なファイルをCIへ追加しません。

`npm test`は生成物の再現性、ハッシュ、Coreの読込み・圧縮ページ・Worker解放、区間索引と変換の境界、10万命令の有界集約、検索・取消・要求の集約を検査します。`npm run test:import`はオフラインのコピーをElectronで開き、File入力とドロップ、形式・圧縮、区間・スレッド移動、取消・不正入力を検査します。入力の後半を止める検査では、EOF前の表示・再生・シークと、完了時の時刻保持、途中表示後の取消まで確認します。`scripts/check-navigation.cts`では二段時間軸、検索からの命令選択、履歴・保存したbookmark、ズーム・pan、区間の連続再生、全体移動の再生状態保持、明示ループ、待機中の手動停止、手動シークと古い応答の競合を確認します。`scripts/check-file-playback.cts`では3スタイルの区間境界で命令位置・カメラ・固定シーンの再利用と高速再生を検査します。演出の時計を停止した同一時刻のcanvas画素も比較します。操作の連打と応答待ち中のcanvas高さも確認します。これらは全描画検査にも含めます。数GBの性能測定や実ログの多数区間比較はローカルで行い、通常CIに巨大なファイルを追加しません。
