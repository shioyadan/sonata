# ローカルトレースの読込み

`Open trace…` とファイルのドロップで、Konataと同じKanata / Onikiri、gem5 O3PipeViewを読み込みます。Kanataの形式不一致だけをgem5へ渡し、壊れた圧縮データや読込みエラーを形式不一致として握りつぶしません。gzipとZstandardはストリーム展開します。URL入力やファイルのアップロードは行いません。

## 保存と表示の境界

- `src/trace-import.cts` はFile選択、進捗、取消、対象スレッド、表示区間の操作を所有します。
- `src/trace-worker.cts` は要求を直列に処理するWorkerの入口です。
- `src/trace-file.cts` はKonataの`parseTraceFile`を呼び、`ParsedTrace`と`PagedOpStore`の寿命、区間索引を所有します。
- `src/trace-window.cts` は有界な命令集合をSonataの再生形式へ変換します。ファイル・DOM・GPUには依存しません。
- `src/replay-model.cts` の`loadData`で準備が成功してから、描画側が保持する再生状態へ反映します。同梱デモの読込みも同じ入口を通ります。

FileをWorkerへ渡しても、ファイル全体を文字列やArrayBufferへ展開しません。Konataの圧縮ページ、展開ページのキャッシュ、命令キャッシュを使います。Zstdの入力展開とページ圧縮はさらに専用Workerで行います。画面へ返すのは進捗、ファイルの概要と選択区間のコンパクトな命令だけです。未完成の全命令を繰り返しコピーする処理はありません。

Parserが命令を保存する時点で、1024 IDごとの最小fetch時刻・最大終了時刻・実在IDのビット集合を索引化します。Coreの最初の`onTrace`で公開された`MutableOpStore.setOp`を観測し、保存処理自体は元の実装へ渡します。最初の公開前に命令が保存されていないことを検査し、Core更新で契約が変わった場合は失敗させます。Sonataの索引構築・区間選択では0から最大IDまで走査せず、疎なIDも扱えます。固定Coreのgem5パーサー内部にはID間隔の走査が残るため、形式を問わず間隔に依存しないという保証ではありません。区間変更では重なるブロックだけを展開します。fetch時刻だけで絞ると、左境界より前から続くロード待ちなどを失うため、生存区間の交差を確認します。区間に含めた命令のステージ・終了時刻は切り詰めません。各ブロックに長寿命命令がある場合は多くのブロックを再確認するため、検索時間が常に一定とは限りません。

圧縮済みページと索引もRAM上にあります。ディスク退避や無制限サイズの保証ではありません。新しいファイルを開くと前のファイルのstoreを閉じ、同梱デモへ戻ってから読み込みます。取消・デモ選択・ページ終了でもAbortSignalと`close`で解放し、応答がなくてもWorkerの終了期限を設けています。

## 区間と観測値

全体の範囲から開始サイクルを指定し、16 / 32 / 128 / 512サイクルを選択します。下部タイムラインの再生・ループはこの区間内です。次の区間への移動は`Next`、前は`Previous`で行います。複数スレッドは一つずつ表示します。未完了命令は最後の観測ステージに保持し、コミットや未来のROB解放を追加しません。Kanataの`eof`だけでなく、gem5の`retired=false / flush=false`も未完了です。gem5 Coreの終端時刻が最後のretireまででも、記録されたステージの最大時刻を表示範囲に含めます。tick変換で負値になった未完了末尾のstage終端は、終了未観測として扱います。

ステージの役割はKonataの構造検出を選択命令に適用します。判定できない場合は名前と時刻を保った直列の前段表示とし、架空のallocation / issue / completionを作りません。表示区間を変えると推定構造や容量が変わる場合があります。デモ抽出器のファイル名別のCPU設定やレジスタ数、固定tick倍率、特定ISAの依存推定は適用しません。レジスタ値・Top-downは未観測、依存関係はログにある辺だけを使います。

描画用の上限は`trace-window.cts`の`limits`にまとめています。命令・ステージ数、同時命令数、スケジューラ・ROBのセル数、同時経路数を確認し、黙って命令を減らさず、上限と対処を表示します。役割を検出しても単一FIFOとして表現できない区間では理由を表示します。短い区間を選ぶと総命令数を減らせますが、瞬間的な占有数そのものが大きい場合は区間を短くしても解決しません。

## オフラインビルドと検査

KonataのTypeScript原本、固定リビジョン、ファイルハッシュは`vendor/konata-core/`に保持します。WASMを内包する圧縮器と各ライセンスは`vendor/wasm-zstd/`に固定します。開発時の`npm run core:generate`でTypeScriptを変換し、生成済み`browser.cjs`をコミットします。通常の`npm run build`はこれを使うため、Nodeの標準機能だけで完結します。ライセンス全文とWorker本文も配布HTMLへ含めます。

`npm test`は生成物の再現性、ハッシュ、Coreの読込み・圧縮ページ・Worker解放、区間索引と変換の境界を検査します。`npm run test:import`はオフラインのコピーをElectronで開き、File入力とドロップ、形式・圧縮、区間・スレッド移動、取消・不正入力を検査します。基本描画CIと全描画検査にも含めます。数GBの性能測定はローカルで行い、通常CIに巨大なファイルを追加しません。
