# 外観のスタイル

右上の Orbit / Top view / Cinema の下にある **Neon / Aluminum / Paper** ボタンで外観を切り替えます。3つのボタンは1行に並び、視点ボタンと同じ文字・余白・枠・選択状態を使います。スマートフォンでも各ボタンに44px以上の操作領域を確保します。初期表示は Neon です。

| | Neon | Aluminum | Paper |
| --- | --- | --- | --- |
| 印象 | 暗い基板と光の流れ | 銀色の精密な模型 | 白い厚紙を組み立てた模型 |
| 部品 | 暗い面と発光する輪郭 | 細い研磨筋、明るい金属面と暗いくぼみ | 厚紙の積層、折り筋、微細な繊維 |
| 命令 | 発光する粒子 | 色付き上面と銀色の縁を持つ金属パック | 色紙の小さな折り箱 |
| 配線・活動 | 加算合成、光跡、ブルーム | 常設線は青灰色、活動は命令色 | 常設線は灰色、活動は命令色 |
| 照明 | 発光・霞・フラッシュ時の歪み | 広い環境反射と研磨方向に広がるハイライト、投影影 | 紙面の拡散光と投影影、控えめな光沢 |
| 周囲の UI | 暗いパネル | 淡い青灰色のパネル | 明るい生成りのパネル |

切り替えてもデモ、サイクル、再生・停止、カメラ、ピン留めした命令、演出の ON / OFF は保たれます。デモを変えたときもスタイルは維持します。ページを再読み込みすると Neon に戻ります。

Aluminum / Paper では **Bloom** を無効にし、`Not used` と表示します。Neon に戻すと以前の値で使えます。**Trails**、**Instruction stream**、**Motion effects**、**Auto orbit** はすべてのスタイルで使えます。接地影や面の陰影は造形上の演出で、プロセッサの活動量を表しません。未観測のレジスタ値・割り当て・依存関係の扱いは共通です。

## アルミ

**Aluminum** は明るい銀色の部品と、少し暗い台座・くぼみを組み合わせます。大きな面に細いヘアラインを付け、視点によって変わる広い反射と面取りのハイライトで金属感を出します。意味色は識別帯と命令へ残します。周囲のUIも共通の明るいテーマを使い、背景と文字を青灰色に揃えます。

研磨筋には生成テクスチャを一方向へ伸ばして使い、面の切り替え前の位置微分を同じUV面へ投影してmipmapの参照に渡します。環境反射は明るい天井と広い光源を式で近似します。実際の部品を鏡のように映す処理や、外部画像は使いません。

命令は少し厚みのある面取り円盤です。上面の広い範囲を命令色にし、銀色は細い縁と側面へ残します。16角の側面・上下の面取り・平らなふたと底面から作り、寸法と50面の一覧を `geometry.metalPuck` / `metalPuckPlanes` からCPU接地と本体・影のGLSLへ共用します。側面の法線は丸く補間して見せます。常に正立し、待機・移動・commit / squash・シークでも回転せずに滑ります。

## 紙模型

**Paper** は白い厚紙を組み立てた模型です。台と台座の側面には薄い積層線、本体には角の内側の折り筋を描き、面には微細な粒と繊維を添えます。紙面と小さな識別帯の光沢を抑え、印刷した色のように見せます。

命令は色紙を折った不透明な小さな折り箱です。ふたの継ぎ目・側面の折り返し・白い紙の断面と微細な繊維を使います。正立した箱の6面をCPUの接地計算、本体、影で揃えます。単位形状の半辺 `1 / √3` を `geometry.paperBoxHalfExtent` からGLSLへ渡し、外接半径を保ちます。

移動中も上面を上に保ち、転がさずに滑らせます。**Motion effects** の ON / OFF、commit / squash、シークでもこの向きを維持し、退場時のフェードは保ちます。固定部品の配置・形状・支持面と、命令の意味色・外接半径・水平経路はAluminumと共通です。形の違いに応じて中心の高さと接点は変わります。

紙箱の模様は面ごとの座標で描き、線幅とmipmapには物体座標の微分を同じ面へ投影して使います。面を切り替えたUVを直接微分すると、角で折り筋や断面が途切れるためです。積層線は画素幅に応じて平均色へ戻します。紙面は共有テクスチャの粒と繊維を使い、積層線や折り筋は通路や記録値を表しません。

## 命令の大きさと待機場所

Aluminum / Paper の命令は外接半径0.12で描き、場所・待機・実行・commit・squash によって伸縮させません。同じ命令が同じ物体として移動するようにするためです。カメラとの距離による見かけの大きさは異なります。活動の違いは色や周囲の通知で伝えます。Neon の光点には大きさ・明るさの演出を使います。

密なスケジューラは、行との対応を保った2列の千鳥配置にします。隣接する列の間隔は0.28、行のピッチは最小0.14とし、同じ列の駒同士にも0.28以上の間隔を確保します。依存行列と筐体の奥行きも行数に合わせて広げます。56行の場合は、長くなったユニットの見出しを手前へ出し、物理レジスタの見出しとの重なりを避けます。

スケジューラの横線・縦線は、それぞれ表示エントリ1個に1本ずつ対応します。56エントリなら横56本・縦56本で、外枠は別です。横線は待機位置の行へ、縦線は依存セルの列へ揃え、8エントリごとに強調します。表示容量はトレースの最大占有数を8単位で切り上げた値（最小16）で、CPU設定上の容量の断定ではありません。

Rnを含む前段の命令は、同じFetchサイクルの束ごとにX方向0.32、束内の命令ID順にZ方向0.38の間隔で並べます。横位置を全前段で引き継ぎ、束の一部が進んでも空いたlaneを詰めません。束全体が退出補間を終えた後に後続を前詰めし、同じサイクルへのシークとスタイル切り替えで同じ配置へ戻ります。表示用の場所の数はハードウェア容量を表しません。時刻・待機時間・RAT更新は変えません。詳しくは[表示と記録の対応](visualization.md#データの扱い)を参照してください。

ROB は96エントリを超えるデモで8列、それ以外は4列に折り返します。192エントリは8列×24行、48エントリは4列×12行です。8列の場合は左端を保って筐体の幅を3.0に広げ、メモリ待ちからの接続線が進行方向を保つようにします。FIFO の割り当て・head / tail・commit の順序と論理スロット数は変更しません。この配置は全スタイルで共有します。

`sonata.instructionLayout` で半径とスケジューラ・ROB・Rnの全配置先を、`sonata.schedulerGrid` で横線・縦線の端点を参照できます。検査では全5デモの配置間隔が駒の直径より大きいこと、見どころの時刻を移動しても全命令の半径が同じであることを確認します。表示と影へ送ったGPUバッファの半径、スケジューラの実際の線数も照合します。

## 動く命令の接地

Aluminum / Paper の命令は、ユニット上で待機・処理している間はその面に接して表示します。金属パック・紙箱の面と角から接する高さを求めます。ステージ間は出発・到着地点の接地高さを補間して渡り、隙間で土台まで落としません。入場は最初のステージの高さ、COMMIT後の退場は出口の高さを保ちます。squash後の散開は下にある板や卓上へ接地させます。Neon は浮遊・放物線の高さを保ちます。

支持面には実際に描画する固定部品と開いた溝の上向き三角形を使います。駒の支持点が輪郭の外へ出る場合は輪郭上を数値探索し、縁で支えられる高さを求めます。これにより単に外接球の半径を足す場合の浮きや、角の埋まり込みを抑えます。頂点・辺の接点を世界座標から戻すときは局所座標で1e-9の丸め誤差を許容し、境界上の点を形の外と誤判定しないようにします。

ステージ間の経路は16分割して途中の支持面を調べ、両端より高いユニットを横切る場合には滑らかな弧で越えます。障害物の判定には一定の外接球を使い、最後に実際の形状で貫通を防ぎます。ユニット内の垂直な段差は面の形状に従います。重力・摩擦や、命令同士の衝突は計算しません。

表示・命令選択・追跡マーカー・投影影には同じ表示位置を渡します。Trails もこの経路を使い、Aluminum / Paper では選択中の命令だけに5区間の軌跡を表示します。全命令へ軌跡を付けると、過去位置の接地・移動も毎フレーム調べるためです。Neon では全命令の軌跡を使います。通知や依存関係を示す線・光点は情報表示として共通の位置を保ちます。

停止やカメラ操作では接地結果を再利用します。再生中も位置・大きさ・姿勢が同じ駒は再計算しません。キャッシュは命令ごとに最大16時点、直前の姿勢条件と移動区間の支持面標本を保持し、デモ・スタイル・WebGL復旧による組立時に破棄します。形状もキーへ含め、切り替え前の接地を再利用しません。

診断APIの `sonata.pieces` は表示位置の `position`、元の `pathPosition`、接触点の `contact`、移動区間の `transfer` を返します。面から離れて渡っている間の `contact` は `null` です。両実体の `rotation` は常に単位クォータニオンです。`sonata.particles` の画面位置とクリック判定も同じ表示位置です。

## 実装上の分離

- `src/scene.cts` 冒頭のプリセットは意味ごとの色、背景、Top-down とタイムラインの配色、材質の指定を持ちます。Aluminum / Paper は共通の意味色と、大きな面・常設線・待機表示の `structure` を分けます。`surface` は台の色、粗さ、模様の強さ、光源位置と紙・アルミ材質の指定をまとめます。
- `src/scene.cts` と `src/activity.cts` は共通の配置・水平経路から部品と命令の描画データを作り、`src/renderer.cts` は材質・合成方法を選びます。実体の部品は丸い角と法線を持つ共有形状、命令は `src/shaders.cts` の `createPieceShaders` で画素ごとの交点を求めてインスタンス描画します。
- `src/geometry.cts` は固定部品と溝の三角形を空間格子へ分け、紙箱・金属パックの支持面との接触高さを求めます。描画シェーダーと形状の寸法を揃え、経路の障害物判定にだけ外接球を使います。転がり軌道や屈折用の背景コピーは持ちません。
- `src/appearance.css` の `data-theme=light` は Aluminum / Paper で共用し、パネル、ラベル、凡例、ダイアログなどを明るい画面に合わせます。
- `src/replay-model.cts` と同梱トレースは外観から独立しています。

スタイル変更では `loadTrace` を呼びません。静的なGPUバッファとラベルを作り直し、現在のサイクルを再描画します。以前のバッファとVAOは削除します。命令の水平経路・サイズ・選択は共通です。構成の詳細は [ソースの構造](architecture.md) を参照してください。

3種類の組み込みプリセットに必要な処理を持ち、削除した外観の専用処理を共通設定へ残さない方針です。新しい外観を追加する場合は、配色だけで十分か、形状・合成・文字の読みやすさも変える必要があるかを判断します。設定ファイルだけで任意の外観へ変更できるプラグイン機構ではありません。

## 部品の材質と影

Aluminum / Paper は、モジュールの厚み、並列の溝、レジスタの並びを物体として捉えやすい方向です。Neon は、密な流れや活動の強弱を発光で捉えやすい方向です。全体表示の命令は小さく、細部には拡大操作を使います。配線は高密度のデモでも部品を隠さないよう細く保ちます。

面は平らな法線を保ち、面取り部分だけを滑らかに補間します。照明はLambertの拡散光、広いBlinn–Phongの鏡面反射、控えめなFresnelを組み合わせます。材質の色はsRGBの区分的な変換式で線形化し、照明を計算した後でsRGBに戻します。塗装面では強い反射だけを緩やかに圧縮して白飛びを抑えます。画面全体をHDR合成する方式ではありません。

繊維・研磨筋・微細なむらには、実体のスタイルを初めて使うときにコードで生成する1枚のテクスチャを使います。周期的な格子で境界をつなぎ、mipmapで縮小時の細かい模様を平均化します。模様は各部品の座標に固定し、外部画像は追加しません。

固定した部品の投影影は、組み立て時に最大2048角のdepth textureへ描きます。カメラ移動と通常再生では作り直さず、受け手の材質シェーダーで比較フィルターを使って境界を和らげます。接地部分には丸い輪郭から薄くなる影を重ね、部品の重なりと板への接地を示します。Neonに戻すと投影影のターゲットを解放します。

固定部品は支持面に密着させます。卓上と二層の板、板と各台座、台座と本体、本体上のセル・レールの隙間を閉じます。`box` / `housing` の `supportY` に下の部品の天面を渡し、底面だけを伸ばします。天面の高さと面取りは維持するため、命令の経路・ポート・情報表示の座標は共通です。Neonは `supportY` を使わず、部品間の隙間を保ちます。

動く命令も同じ光源から台・ユニット・溝に影を落とします。描画と共通の形状・姿勢・中心座標を光源から描くため、紙箱と金属パックの輪郭や台との高さが影に反映されます。移動中と待機中の両方で有効で、消え際は影も薄くなります。

命令の影は固定部品とは別の最大2048角のdepth textureと、輪郭・不透明度を持つR8 textureに保存します。サイクル・形状またはデモ等の描画条件が変わったときだけ描き直し、停止中やカメラ操作中は再利用します。受け手では深度の比較フィルターと被覆率の補間を使い、2回のテクスチャ参照で縁を和らげます。Neonへ戻ると両テクスチャとframebufferを解放します。診断APIの `sonata.renderer.pieceShadows` で解像度・駒数・更新回数を確認できます。

密集部が黒くなりすぎないよう光源に最も近い駒の影を使い、重なる影の濃さは加算しません。命令同士に影を投影する処理、光源の面積と距離に応じた正確なぼけは未実装です。命令が固定部品の影を受ける処理は共通です。影・艶・表面の模様は外観の演出であり、命令の占有・値の既知／未知・活動量は記録表示から判断します。

明るい不透明な面では、遠い俯瞰で奥行きの丸め誤差による縞が目立ちました。depthを24 bitにし、near planeをカメラ距離の1%（最小0.1）へ調整して、薄い板と重ね描きの干渉を抑えています。MSAAはこのdepth形式とcolor形式で共通に使えるサンプル数を選びます。

## 画面全体の色の配置

大きな面を落ち着いた中性色へ揃え、色のある命令を追いやすくします。ユニット全体を種類別に塗り分けると命令と同じ色面が画面を占めるため、識別は細い帯と小さな端子・ラベルに集めます。

| 対象 | 配色と役割 |
| --- | --- |
| 背景・台・周囲のUI | Aluminumは青灰色、Paperは生成り。本体との明度差で部品を分ける |
| ユニット本体・縁 | 銀色や厚紙の中性色。面取り、艶、明暗で立体を見せる |
| 台座・溝・セル | 本体より濃い中性色。材質と明暗で段差を分ける |
| 識別帯・端子・ラベルの番号 | 小さな面積にカテゴリ色を残す |
| 命令・読み出し・更新 | 緑・橙・紫・青などの意味を持つ色 |
| 常設配線・空きスロット・待機中のレジスタ | 灰色。割り当て・空き・未観測は面・枠・斜線で区別する |
| squash・対応の復元 | 赤い表示で異常や巻き戻しを示す |

レジスタの値とRATの対応は待機中も灰色で読み取れます。読み出し・書き戻し・対応更新の時刻には活動色を使います。Aluminum / Paperでは、レジスタの活動と実行パイプの入口・出口を示す点をNeonの半分の直径に抑え、命令を覆いにくくしています。依存関係や完了・フラッシュの通知は意味を保ちます。

周囲光は明るい中立色を保ち、側面の向きによる陰影と接触部の影を残します。照明全体を暗くせず、色を置く面積で強弱を付けます。意味を持つ色の値と、台やユニットの材質色は独立して調整します。

## 比較と検証

```sh
npm run test:styles
# 画面のない Linux
xvfb-run -a -s '-screen 0 1600x1100x24' npm run test:styles
```

本体と生トレースを隔離したHTTP配信先へコピーし、それ以外の通信を禁止して、全5デモのスクリーンショットと見どころの時刻で3スタイルの状態を比較します。Aluminum / Paperの水平経路・色・半径・インスタンス数を照合し、全命令の向きが固定されていることを確認します。高さと接点は金属パック・紙箱の実際の面とGPUへ送った座標から検査します。

時計・カメラ・命令選択・ROB・レジスタ・依存行列・Top-down・ポートと配線の座標、再生の継続、Bloom設定の復帰、描画画素を確認します。スタイルボタンが3種類だけで指定順の1行に並び、視点ボタンと文字・余白・枠・選択表示が一致することを検査します。材質ごとのモバイル4サイズではDPR 2の描画画素・44px以上の操作領域・ヒット判定と、設定パネルを開いた状態からのデスクトップ復帰を検査します。共通の実タッチ・Spaceによる切替、再生ショートカットとの分離、ピンチと移動は `test:mobile` で一度だけ確認し、全 `test:render` にも含めます。

実トレースの移動・長い待機・一時停止・巻き戻し・デモ再読込み・commit / squash後の姿勢を検査し、Motion effects切替時に駒の向きと中心の描画画素が変わらないことを照合します。接地は紙箱・金属パック・障害物判定用の外接球で傾斜面・段差・辺を検査します。動く命令の影は同じフレームから影だけを除いた画素と比較し、移動・停止・シークでの復元と再利用を確認します。

比較画像は `artifacts/screenshots/sonata-style-<demo>-neon.png`、`sonata-style-<demo>-aluminum.png`、`sonata-style-<demo>-paper.png` です。画素差はUIを除いたキャンバスから読み取ります。中間の拡大は `sonata-style-<style>-materials.png`、最大拡大は `sonata-style-<style>-detail.png`、モバイルは `sonata-style-<style>-mobile-<width>.png` に保存します。診断値は `sonata.visualStyle`、`sonata.pieces`、`sonata.selectedID`、`sonata.renderer` から確認できます。

ブラウザ検査では全3スタイルでWebGL context loss / restoreを発生させ、再生と材質・影・描画画素の復旧を確認します。MSAAを使えない環境も注入し、両実体の画素・WebGLエラーを確認します。命令描画直前の下地を黒・白へ差し替えても駒の中心画素が変わらないことを検査し、命令を除いた対照フレームで下地の差が現れることも確認します。拡大画像は `sonata-style-aluminum-no-msaa.png` / `sonata-style-paper-no-msaa.png` に残します。

この検査は `npm run test:render` と手動の全描画CIに含みます。Electron / SwiftShaderでの検証であり、実機Safari / Chromeの見た目やGPUの速度は別途確認が必要です。描画パスや分岐の削減だけで高速化を断定せず、通常再生と同じ条件で負荷を比較します。
