# 外観のスタイル

右上の Orbit / Top view / Cinema の下にある **Neon / Blocks** ボタンで外観を切り替えます。視点ボタンと同じ文字・余白・枠・選択状態の表示を使い、スマートフォンでは両方とも44px以上の操作領域を確保します。初期表示は Neon です。

| | Neon | Blocks |
| --- | --- | --- |
| 印象 | 暗い基板と光の流れ | 明るい中性色の模型と色付きの命令 |
| 部品 | 暗い面と発光する輪郭 | 生成り色のブロックと木の台座、小さな識別帯 |
| 命令 | 発光する粒子 | 色付きの Cut crystal に固定 |
| 配線・活動 | 加算合成、光跡、ブルーム | 常設の線は灰色、活動する線・点と短い軌跡は命令色 |
| 照明 | 発光・霞・フラッシュ時の歪み | 面の陰影・視点に応じた反射・部品と命令が落とす影 |
| 周囲の UI | 暗いパネル | 紙を思わせる明るいパネル |

切り替えてもデモ、サイクル、再生・停止、カメラ、ピン留めした命令、演出の ON / OFF は保たれます。デモを変えたときもスタイルは維持します。ページを再読み込みすると Neon に戻ります。

Blocks では **Bloom** を無効にし、`Not used` と表示します。Neon に戻すと以前の値で使えます。**Trails**、**Instruction stream**、**Motion effects**、**Auto orbit** は両方で使えます。接地影や面の陰影は造形上の演出で、プロセッサの活動量を表すものではありません。未観測のレジスタ値・割り当て・依存関係の扱いは共通です。

## 命令の表現

Blocks の命令は、平らなカット面が光を拾う色付きの **Cut crystal** に固定します。中性色のユニットと、角のある色付きの命令で役割を分けます。形状・材質を選ぶ Look と、比較用の試作は削除しました。

緑・橙・紫・赤などの配色は、命令の種類や状態を表します。カット面の明暗・背景の透過・回転は外観の演出で、記録値を表すものではありません。全体表示と拡大の両方で、輪郭・命令色・動きの見え方を確認します。

## 命令の大きさと待機場所

Blocks の命令は外接半径0.12で描き、場所・待機・実行・commit・squash によって伸縮させません。同じ命令が同じ物体として移動するようにするためです。カメラとの距離による見かけの大きさは異なります。活動の違いは色や周囲の通知で伝えます。Neon の光点には従来の大きさ・明るさの演出を使います。

密なスケジューラは、行との対応を保った2列の千鳥配置にします。隣接する列の間隔は0.28、行のピッチは最小0.14とし、同じ列の駒同士にも0.28以上の間隔を確保します。依存行列と筐体の奥行きも行数に合わせて広げます。56行の場合は、長くなったユニットの見出しを手前へ出し、物理レジスタの見出しとの重なりを避けます。

スケジューラの横線・縦線は、それぞれ表示エントリ1個に1本ずつ対応します。56エントリなら横56本・縦56本で、外枠は別です。横線は待機位置の行へ、縦線は依存セルの列へ揃え、8エントリごとに強調します。Blocks では細線のコントラストも確保します。この表示容量はトレースの最大占有数を8単位で切り上げた値（最小16）で、CPU設定上の容量の断定ではありません。

Rn の命令は滞在区間の重なりから別々の配置先を割り当て、X方向0.32・Z方向0.38の間隔で並べます。命令番号をfetch幅で割った余りだけで配置すると、8-wideの段に16命令が滞在する場面で重なるためです。退場の補間が終わるまで配置先を再利用せず、待機中には詰め直しません。表示用の場所の数はRnのハードウェア容量を表しません。時刻・待機時間・RAT更新は変えず、同じサイクルへのシークとスタイル切り替えで同じ配置へ戻ります。

ROB は96エントリを超えるデモで8列、それ以外は4列に折り返します。192エントリは8列×24行、48エントリは4列×12行です。8列の場合は左端を保って筐体の幅を3.0に広げ、メモリ待ちからの接続線が進行方向を保つようにします。FIFO の割り当て・head / tail・commit の順序は共通で、論理スロット数は変更しません。この配置は Neon と Blocks で共有し、スタイルを往復しても水平経路を保ちます。

`sonata.instructionLayout` で半径とスケジューラ・ROB・Rnの全配置先を、`sonata.schedulerGrid` で横線・縦線の端点を参照できます。検査では全5デモの配置間隔が駒の直径より大きいこと、見どころの時刻を移動しても全命令の半径が同じであることを確認します。表示と影へ送った GPU バッファの半径、スケジューラの実際の線数も照合します。

## 命令の回転

Blocks の Cut crystal は、命令が進む方向と水平移動距離に合わせて回転します。カット面の向きや明暗が変わるため、移動を形でも追えます。反射は光源と視点に合わせて計算します。

待機中は回らず、一時停止で回転も止まります。巻き戻し・直接シーク・再読込みでも、同じデモの同じサイクルなら同じ姿勢になります。カメラやスタイルを切り替えても姿勢を保ちます。**Motion effects** を OFF にすると固定した向きで表示し、ON に戻すとそのサイクルに対応する姿勢へ戻ります。

これは移動を示す演出です。水平面上の移動量から回転を求め、上下の浮き上がりだけでは回しません。回転量は表示用の半径0.85で控えめにし、見た目のサイズに対して急に高速回転しないようにしています。重力・摩擦を積分する物理シミュレーションではありません。水平経路・再生時刻は共通ですが、Blocks の描画高さは形状と支持面から求めます。

## 動く命令の接地

Blocks の命令は、ユニット上で待機・処理している間はその面に接して表示します。回転した Cut crystal の面・角から接する高さを求めます。ステージ間は、出発・到着地点の接地高さを補間して渡ります。隙間で土台まで落としてから登らせる動きは行いません。入場は最初のステージの高さ、COMMIT後の退場は出口の高さを保ちます。squash後の散開は下にある板や卓上へ接地させます。Neon は従来の浮遊・放物線の高さを保ちます。

支持面には実際に描画する固定部品の上向きの三角形と、開いた溝の三角形を使います。面に対する駒の支持点が輪郭の外へ出る場合は、輪郭上を数値探索し、縁で支えられる高さを求めます。これにより単に外接球の半径を足す場合の浮きや、回転した角の埋まり込みを抑えます。ステージ間の経路は16分割して途中の支持面を調べ、両端より高いユニットを横切る場合には滑らかな弧で越えます。障害物の判定には一定の外接球を使い、駒の回転で経路が切り替わるのを避けます。最後に実際の形状で貫通を防ぎます。ユニット内の垂直な段差は面の形状に従います。跳躍・重力・摩擦や、命令同士の衝突は計算しません。

表示・命令選択・追跡マーカー・投影影には同じ表示位置を渡します。Trails もこの経路を使い、Blocks の命令の軌跡は5区間に抑えます。通知や依存関係を示す線・光点は情報表示として従来の位置を保ちます。ポートと配線の配置、記録された処理順・時刻・ROB・レジスタの状態は変更しません。

停止やカメラ操作では接地結果を再利用します。再生中も位置・大きさ・姿勢が同じ駒は再計算しません。キャッシュは命令ごとに最大16時点、直前の姿勢条件と移動区間の支持面標本を保持し、デモ・スタイル・WebGL 復旧による組立時に破棄します。診断 API の `sonata.pieces` は表示位置の `position`、元の `pathPosition`、接触点の `contact`、移動区間の `transfer` を返します。面から離れて渡っている間の `contact` は `null` です。`sonata.particles` の画面位置とクリック判定も同じ表示位置です。

## 実装上の分離

- `src/scene.js` 冒頭のプリセットは意味ごとの色、背景、Top-down とタイムラインの配色、材質の指定を持ちます。Blocks は意味を持つ `palette` と、大きな面・常設線・待機表示の `structure` を分けます。`surface` は木の色、粗さ、木目の強さ、光源位置をまとめます。
- `src/scene.js` と `src/activity.js` は共通の配置・水平経路から部品と命令の描画データを作り、`src/renderer.js` は材質・合成方法をスタイルに応じて選びます。Blocks の部品は丸い角と法線を持つ共有形状、命令は同ファイル内の `createCrystalShaders` の Cut crystal 専用シェーダーで画素ごとの交点を求めてインスタンス描画します。通常の透明合成を使い、ブルームの4パスと発光用の最終加工を省きます。
- `src/geometry.js` の回転計算は経路上の移動をクォータニオンで積み重ね、時刻から回転を求めます。フレーム間の差分や装飾用の時計には依存しません。ステージの境界・曲がり角で区切り、各区間を16分割した姿勢を命令ごとに遅延生成して再利用します。同じ位置の標本はまとめ、デモ変更でキャッシュを解放します。
- 同ファイルの接地計算は固定部品と溝の三角形を空間格子へ分け、Cut crystal の姿勢から支持面との接触高さを求めます。描画シェーダーと形状の寸法を揃え、経路の障害物判定にだけ外接球を使います。
- `src/appearance.css` の `data-style=blocks` はパネル、ラベル、凡例、ダイアログなどを明るい画面に合わせます。変更箇所と状態の分離は [ソースの構造](architecture.md) を参照してください。
- `src/replay-model.js` と同梱トレースは外観から独立しています。

スタイル変更では `loadTrace` を呼びません。静的な GPU バッファとラベルを作り直し、現在のサイクルを再描画します。以前のバッファと VAO は削除します。命令の駒は共通の水平経路と一定のサイズを使います。移動中と待機中で形状・サイズを保ち、クリックによる命令の追跡も共通です。

現時点では2種類の組み込みプリセットです。追加する場合は、配色だけで十分か、形状・透明合成・文字の読みやすさも変える必要があるかを判断します。設定ファイルだけで任意の外観へ変更できるプラグイン機構ではありません。

## 部品の材質と影

Blocks は、モジュールの厚み、並列の溝、レジスタの並びを物体として捉えやすい方向です。Neon は、密な流れや活動の強弱を発光で捉えやすい方向です。配置は共通なので、同じ再生位置で往復して比べられます。

全体表示の駒は小さく、個々の命令やレジスタの細部には拡大操作が必要です。Blocks の駒は一定サイズにし、スケジューラと ROB は駒の間隔を確保できる配置にしています。配線は細い線を維持し、太いチューブへの置き換えは見送りました。高密度のデモで配線と部品が重なるためです。

拡大時にも立体を読み取れるよう、丸い角の法線、光源位置を使う拡散光、視点に応じた幅のあるハイライト、足元の陰影を追加しました。塗料の色も少し深くして、部品の天面・側面・角を区別しやすくしています。

面は平らな法線を保ち、面取り部分だけを滑らかに補間します。照明は Lambert の拡散光、広い Blinn–Phong の鏡面反射、控えめな Fresnel を組み合わせます。面取りの半径と反射の鋭さは控えめにし、密な部品を大きな丸みでつぶさないようにしています。

材質の色は [sRGB の区分的な変換式](https://www.w3.org/TR/css-color-4/#color-conversion-code)で線形化し、照明を計算した後で sRGB に戻します。単純な 2.2 乗による近似を避けます。塗装面では強い反射だけを緩やかに圧縮して白飛びを抑えます。画面全体を HDR 合成する方式ではなく、材質の照明演算を線形空間で行う構成です。

木目2層と塗膜の微細なむらは、Blocks を初めて使うときにコードで1枚のテクスチャへ生成します。周期的な格子で境界をつなぎ、mipmap で縮小時の細かい模様を平均化します。模様は各部品の座標に固定します。Cut crystal の表面にはむらを加えず、磨いたガラスの艶を出します。外部画像は追加していません。

固定した部品の投影影は、組み立て時に最大2048角の depth texture へ描きます。カメラ移動と通常再生では作り直さず、受け手の材質シェーダーで比較フィルターを使って境界を和らげます。接地部分には丸い輪郭から連続的に薄くなる影を重ね、部品の重なりと板への接地を示します。Neon に戻すと投影影のターゲットを解放します。

Blocks の固定部品は支持面に密着させます。卓上と二層の板、板と各台座、台座と本体、本体上のセル・レールの隙間を閉じ、重さのある模型として見せます。`box` / `housing` の `supportY` に下の部品の天面を渡し、底面だけを伸ばします。天面の高さと面取りは維持するため、命令の経路・ポート・情報表示の座標は共通のままです。接地影は部品の真下を中心とする狭い範囲に置き、光源方向への投影影とは分けます。Neon は `supportY` を使わず、従来の部品間の隙間と浮遊感を保ちます。

動く命令も、同じ光源から台・ユニット・溝に影を落とします。描画と共通の形状・回転・中心座標を光源から描くため、カット面の向きや台との高さが影に反映されます。移動中と待機中の両方で有効です。命令の消え際は影も薄くなり、透過を持つ Cut crystal に合わせて影の濃さを抑えます。

命令の影は固定部品とは別の最大2048角の depth texture と、輪郭・不透明度を持つ R8 texture に保存します。サイクル・Motion effects またはデモが変わったときだけ描き直し、停止中やカメラ操作中は再利用します。受け手では深度の比較フィルターと被覆率の補間を使い、2回のテクスチャ参照で縁を和らげます。Neon へ戻ると両テクスチャと framebuffer を解放します。診断 API の `sonata.renderer.pieceShadows` で解像度・駒数・更新回数を確認できます。

密集部が黒くなりすぎないよう、光源に最も近い駒の影を使い、重なる影の濃さは加算しません。命令同士に影を投影する処理、透明な材質を通った色付きの影やコースティクス、光源の面積と距離に応じた正確なぼけは未実装です。命令が固定部品の影を受ける処理は共通です。影・艶・木目は見た目の演出であり、命令の占有・値の既知／未知・活動量は既存の記録表示から判断します。

明るい不透明な面では、遠い俯瞰で奥行きの丸め誤差による縞が目立ちました。depth を24 bitにし、near plane をカメラ距離の1%（最小0.1）へ調整して、薄い板と重ね描きの干渉を抑えています。MSAA はこの depth 形式と color 形式で共通に使えるサンプル数を選びます。

## 画面全体の色の配置

大きな面を落ち着いた中性色へ揃え、色のある命令を追いやすくします。ユニット全体を種類別に塗り分けると、移動する命令と同じ色面が画面を占めます。そのため、種類の識別は細い帯と小さな端子・ラベルに集めます。

| 対象 | 配色と役割 |
| --- | --- |
| 背景・木の台・周囲の UI | 背景と UI は生成りの紙色、台は淡い木肌。弱い木目で温かみを出す |
| ユニット本体・縁 | 温かいアイボリー。面取り、艶、明暗で立体を見せる |
| 台座・溝・セル | 台座は本体より濃い木肌、溝とセルは茶灰色。材質と明暗で段差を分ける |
| 識別帯・端子・ラベルの番号 | 小さな面積にカテゴリ色を残し、各ユニットを識別する |
| 命令・読み出し・更新 | 緑・橙・紫・青などの意味を持つ色。活動のある場所へ視線を導く |
| 常設配線・空きスロット・待機中のレジスタ | 茶色寄りの灰色。割り当て・空き・未観測は面・枠・斜線で区別する |
| squash・対応の復元 | 従来の赤い表示で異常や巻き戻しを示す |

レジスタの値と RAT の対応は待機中も灰色で読み取れます。読み出し・書き戻し・対応更新の時刻には従来の色を使います。レジスタの活動と稼働中の実行パイプの入口・出口を示す点は、Blocks では直径を半分に抑え、命令の駒を覆いにくくしています。依存関係や完了・フラッシュの通知は意味を保ちます。

周囲光は明るい中立色を保ち、側面の向きによる陰影と接触部の影を残します。落ち着きを出すために照明全体を暗くせず、色を置く面積で強弱を付けます。意味を持つ色の値と、台やユニットの材質色は独立して調整します。

灰白色の本体と緑寄りの灰色だけでは冷たい印象になるため、中性色にも色温度の差を付けます。本体は生成り、下に見える台座は木肌、溝・文字・配線は茶灰色とし、台座にも既存の木目を使います。画面全体へ暖色のフィルターを掛けず、命令の緑・橙・紫・赤と照明の色は保ちます。黄味の強い広い面にならないよう、背景は木の台より白く、台座は本体より一段濃くしています。

Cut crystal は背景の色も透かすため、部品や台の配色が命令の見え方に影響します。暗く見える場合は命令の色だけでなく、背景の明度と色の面積も確認します。

## Cut crystal の描画

命令は六頂点の描画領域だけを GPU へ送り、画素ごとに視線と形状の交点・法線・奥行きを計算します。外接球で範囲を絞り、軸方向の6面と斜めの8面で光線を切り詰めます。カット面は陰影だけでなく輪郭と奥行きにも反映され、板や部品との前後関係に使われます。

命令の色は明るい顔料として保ち、背景の透過を0.40の比率で混ぜます。描画直前の背景を半解像度で保存し、屈折率1.5の近似でずらして参照します。視線の角度に応じた反射と、窓・室内の明暗を重ねます。環境の映り込みは方向から生成し、外部画像を必要としません。表面には木目や濁りを加えません。

背景には既存のブルーム用ターゲットを再利用します。MSAA がある場合は同じ大きさへ解決してから縮小し、MSAA がない場合も読み元と描画先を分けます。

命令ごとの回転をインスタンス属性で渡し、視線を命令の座標系へ変換して交点を求めます。カット面の法線を世界の座標へ戻して、光源・視点に応じた明暗を計算します。命令の軌跡は線を保ち、途中の丸い点は Blocks では省いて本体を追いやすくします。完了通知など、別の意味を持つ点は維持します。

背景は描画済みの画面から参照する近似です。画面外の景色、命令同士の多重透過、物理的な光の散乱・コースティクスは再現しません。回転も物理シミュレーションではなく、移動距離に対応する演出です。

## 比較と検証

```sh
npm run test:styles
# 画面のない Linux
xvfb-run -a -s '-screen 0 1600x1100x24' npm run test:styles
```

検査は単一 HTML を一時フォルダへコピーして外部アクセスを禁止し、全5デモのスクリーンショットと見どころの時刻で両スタイルの状態を比較します。時計・カメラ・命令選択・ROB・レジスタ・依存行列・Top-down・ポートと配線の座標、再生の継続、Bloom 設定の復帰、実際の描画画素を確認します。命令が Cut crystal に固定され、同じサイズを保つことも検査します。

スタイルボタンは視点ボタンと文字・余白・枠・選択表示が一致することを確認します。モバイル4サイズでは44px以上の操作領域とヒット判定、実タッチによる切り替え、Spaceによる切り替えと再生ショートカットとの分離を検査します。ピンチと移動、設定パネル、デスクトップへの復帰も含みます。

回転は Node の検査で方向・距離・曲がり角・待機・逆戻り・呼出順からの独立性を確認します。描画検査では実トレースの移動と長い待機、一時停止、巻き戻し、デモ再読込み、commit / squash 後の姿勢、Motion effects の OFF / ON によるカット面の描画画素の変化も確認します。接地は Cut crystal と障害物判定用の外接球で傾斜面・段差・回転を検査し、実際の GPU バッファへ渡した座標・接触点・シーク復元を照合します。

`artifacts/screenshots/sonata-style-<demo>-neon.png` と `sonata-style-<demo>-blocks.png` で同じ時刻・視点を比較できます。画素差は UI を除いたキャンバスから読み取ります。部品の質感が分かる中間の拡大は `sonata-style-blocks-materials.png`、真上と最大拡大は `sonata-style-blocks-top.png` と `sonata-style-blocks-detail.png`、モバイルは `sonata-mobile-blocks*.png` に出力します。診断値は `sonata.visualStyle`、`sonata.pieces`、`sonata.selectedID`、`sonata.renderer` から確認できます。

ブラウザ検査では MSAA を使えない環境も注入し、背景コピー・Cut crystal の描画画素・WebGL エラーを確認します。拡大画像は `sonata-style-blocks-no-msaa.png` に残します。

この検査は `npm run test:render` と CI にも含みます。Electron / SwiftShader での検証であり、実機 Safari / Chrome の見た目や GPU の速度は別途確認が必要です。描画パスや分岐の削減だけで高速化を断定しません。共有形状と固定した影の再利用で CPU 側の更新を抑えていますが、法線・反射・影の参照は追加の GPU 処理になります。
