# Sonata の可視化仕様

実トレースから再現している状態と、表示のための推定・演出を説明します。起動と操作は [README](../README.md)、検証は [開発ガイド](development.md) を参照してください。

## 表現

- 発光する基板の上に、フロントエンド、スケジューラ、並列実行ユニット、ROB、COMMIT を立体配置。
- 整数＝ミント、メモリ＝アンバー、分岐＝紫。左のコード、fetch、後続のステージまで同じ命令色を保ち、シーケンスを追いやすくしています。squash された命令は赤になります。
- 左手前には、実トレースの命令 ID・アドレス・命令文が流れる **Instruction stream**。命令文の長さにかかわらず帯の左端に揃えます。文字の帯がカーブして fetch の入口へ向かい、細かい光へ縮んでいきます。文字も WebGL 内で描画しますが、文字の芯にはブルームを掛けず、輪郭を保ちます。
- 実行ユニットは、角を落とした低い筐体に、命令の進行方向と平行な pipe を並べます。接続線と各管路を 1 対 1 でつなぎ、左から右へ通します。上部を開いた管路、入口・出口のカラー、方向を示す矢印、稼働中の光で形と動きを対応させています。管路を進む小さな光で命令の進行を示します。
- INT／BR は通常の 1 サイクル処理をイメージした短い 1 段のセル、LOAD／STORE は長めの管路として描き分けます。管路の外観は代表的な処理の性格を表すもので、`madd` の 3 サイクル区間など、記録された実行時間はそのまま再生します。
- スケジューラで待つ命令は、実行中より控えめなまま、明るさと大きさを上げて個々の光を見えるようにしています。メモリ待ちは暗め、実行中は明るい光です。空いている pipe は薄い輪郭に留め、稼働時に管路・入口・出口を点灯します。スケジューラ内の依存セルは解決時、commit は終了時刻に合わせて明るくなります。ROB は未完了を暗く、完了直後を明るくし、その後は控えめな READY 表示に落ち着きます。
- フラッシュ通知は画面上部の中央に表示します。記録された squash の発生時には、赤い衝撃波、命令の散開、画面の歪みを重ね、再生速度を落とします。
- 同じ squash のタイミングでコードの帯が逆流します。取り消された命令が赤い取り消し線付きで戻り、一文字ずつ離れて小さく傾きながら薄くなります。散る距離を抑えて少し右上へ漂う、穏やかな分解です。`CODE UNRAVEL` の表示中は文字を手前に保持し、移動とフェードを同時に進め、通常の命令列が入り直します。
- WebGL 2 で立体形状・加算合成の光を描画し、縮小フレームバッファでブルームを生成。ビネットとごく薄い粒状感を重ね、flush 時だけ小さな色収差を加えています。
- ROB は循環 FIFO。末尾へ割り当て、完了しても同じ slot に留まり、先頭から commit します。HEAD の WAIT / READY と TAIL の位置が見え、flush では末尾を巻き戻します。
- メモリ待ちが完了すると、アンバーからミントへ変わる通知の光がスケジューラへ戻ります。行列の外周にある wake-up bus へ戻り、そこから対応する producer の列へ光が走ります。中央の空き位置には飛ばしません。

モジュール間の接続線は、画面のモジュール構成と同じ並列幅を使います。実行ユニットの入口・出口は **N pipes と同じ N 本**で、各 pipe の軸と線の端点を揃えます。スケジューラから物理レジスタへの出口の総数も全実行 pipe の合計に揃えます。各 pipe の出口は合流せず、それぞれ別の ROB 入力へ接続します。メモリ待ちの分岐・復帰も LOAD / STORE の pipe 数に揃えます。フロントエンドは fetch / allocation 幅、ROB → COMMIT と出口は commit 幅です。たとえば gem5 はフロントエンド間が 8 本、INT の両側が 7 本、LOAD / STORE の両側が 6 本、BRANCH の両側が 4 本です。短い抜粋でその全数が稼働しなくても本数は変わりません。これらの幅は元トレースの推定結果で、実機の公称帯域の断定ではありません。

抜粋区間内の実際のピーク通過数は、配線本数とは別に `sonata.connections[].peak` に保持します。滞在時間を通過数として数えず、長い実行区間や連続する同一モジュールの stage は重複計上しません。0 サイクルの scheduler 滞在が stage 範囲から省略された場合は、allocation と execution の開始時刻から通過を数えます。

描画品質は次のように調整しています。

- シーンのオフスクリーン描画に最大 **4× MSAA** を適用し、配線・リング・立体の輪郭を滑らかにします。GPU が対応する color / depth 共通のサンプル数を使います。
- デバイスの画素密度に合わせて描画し、倍率の上限は 2.5、描画面積の上限は約 839 万画素です。GPU のテクスチャ・レンダーバッファの上限も確認します。
- 命令の文字アトラスは各辺を 4 倍にし、mipmap で縮小時のちらつきを抑えます。シーンの depth を保ちながらブルーム抽出後に文字を合成するので、文字の芯がにじみません。
- 光点の中心と外縁は画素の大きさを考慮して滑らかに描画します。ブルームは縦横 1/2 の解像度で生成します。
- 通常時の RGB の色ずれは抑え、粒状ノイズはごく弱くしています。

MSAA の resolve は [WebGL 2 の framebuffer API](https://registry.khronos.org/webgl/specs/latest/2.0/) を使います。`sonata.renderer` で実際の描画サイズ・倍率・MSAA サンプル数を確認できます。

ズームはカメラの距離3〜62の範囲で、通常の Fit（32.5）から最大約10.8倍まで拡大できます。以前の最短距離10に比べ、細部を約3.3倍大きく表示できます。右ドラッグ・ホイール・ピンチ・ズームボタンは同じ範囲を使います。右ドラッグでは回転と命令の選択を行わず、シーン内の右クリックメニューを抑制します。

一時停止はトレースの時刻を止めます。装飾的なリングや自動カメラは動き続けます。初期状態は再生・演出・Auto orbit が ON です。装飾の時間進行と画面の歪みは **Motion effects**、自動カメラは **Auto orbit** で手動で OFF にできます。

## 現在付近の Top-down

再生中は解析の更新に合わせ、割合・数値・基板の帯を毎フレーム補間し、およそ 0.3 秒で追従させます。分類が変わると旧領域と新領域の光がクロスフェードし、分類名も短くフェードします。解析値自体は変更せず、次のサイクルの値を先取りしません。シーク・ステップ・デモ切り替えではその時点の結果へ即座に揃え、再現性を保ちます。Motion effects が OFF のときは補間とフェードを行いません。

Top-down の分類名・割合・細いバーは画面の右下に表示します。左上にはタイトルや説明文を置きません。基板の手前の帯も同じ比率で動きます。Frontend はフロントエンド、Backend はスケジューラから実行・完了待ちまでの領域、Bad speculation は投機実行の領域を縁取ります。命令ごとの待機・活性の明るさは維持します。

画面内の **TOP-DOWN** は、現在を右端とする後方 8 サイクルの移動平均です。区間は `[現在 − 8, 現在)` とし、小数サイクルでは両端の部分区間を重み付けします。固定されたビン単位で窓を切り替えません。画面に `PAST 8 CYC → NOW · ESTIMATE` と表示します。分類名、割合、基板の帯は引き続き毎フレームなめらかに追従します。

リポジトリの `vendor/konata-core/trace_navigator_analysis.ts` にある既存解析器のサイクル別 slot 分類を使います。元の分類は事後解析なので、後で squash される命令も allocation 時点へ遡って Bad speculation に含まれます。Sonata では `scripts/top-down.ts` で commit / squash の観測時刻を追加し、結果が未確定でも割り当てが確認できた仕事は **In flight（FLT）** とし、記録不足の Unresolved（UNK）と区別します。commit を観測すると Retiring（RET）、squash を観測すると Bad speculation（SPEC）へ確定します。主表示では In flight と Retiring を合わせた **Pipeline active** を、Frontend / Backend bound、Bad speculation と比較します。recovery bubble も該当する flush より前には表示しません。gem5 の flush 時刻はパイプライン演出と同じ推定時刻です。元の事後解析結果は `topDown.slots` に保持し、生成時には既存解析器との一致を検査します。

これはトレースから推定した **Top-down-like** の内訳で、実機のハードウェアカウンタ値ではありません。完了までの時間が平均窓より長い区間でも、既知の処理中の仕事は Pipeline active として表示します。Retiring は実際に commit が確認できた分だけで、Bad speculation を先取りしません。現在の commit 数やキャッシュミス率とは異なります。右パネルへの重複表示はなく、Cinema でも表示し、モバイルでは画面の縦横と高さに合わせて配置します。逆方向のシークでも、その時刻までに判明した結果だけで再計算します。

全 5 本に gem5 / RSD の解析結果を埋め込んでいます。

## データの扱い

生成には既存のパーサーとステージ構造推定を使用します。元ログの命令やサイクルを作り替えず、区間に重なる命令を切り出しています。抽出済みのデモを `data/traces.js` に保存します。

命令のステージ、fetch / retire / squash の時刻、キューと ROB の占有数はサンプルに従います。立体的な配線、飛行経路、軌道リング、小さな搬送光、衝撃波は鑑賞用の演出です。衝撃波の描画中心は分岐ユニットに固定しており、原因の命令や物理的なプロセッサ構造を特定するものではありません。

実行 pipe は進行方向を長軸にし、並列の管路をその横に並べています。形状と命令の座標は同じ入口・出口を使い、ステージ冒頭の短い流入のあと、記録されたステージ区間に合わせて管路を通過します。本数は既存のステージ構造推定に従います。抜粋には物理 pipe の識別情報がないため、各命令をどの管路に表示するかは一定の規則による演出です。元ログの issue・completion・終了時刻は変更しません。管路の座標は `sonata.executionPipes` で確認できます。

左の命令の帯は、これから fetch される命令を fetch 時刻・命令 ID 順で最大 24 行先読み表示します。長い命令文は表示幅に合わせて省略します。同時 fetch の命令を短い時間にわたって入口へ集める演出で、物理的な追加キューではなく、占有数や fetch 時刻を変更しません。トレースのサイクルに同期するので、一時停止で帯も止まり、シーク時には同じ位置へ戻ります。サンプル末尾では記録されている残りの命令だけが流れます。

コードの巻き戻しもトレースのサイクルに同期します。flush 発生から 0.9 サイクルで最大 30 行ぶんを逆流させ、赤く取り消し線を付けるのはそのイベントで実際に squash された命令だけです。通過済みの命令も過去の表示として保持します。文字は 0.9〜2.55 サイクルでほどけ、その移動に重ねて 0.9〜3.0 サイクルで滑らかに薄くなります。分解中の文字は基板に隠れない前面の層に描画し、画面上で数十 px 離れるように移動・回転させます。2.8 サイクルから通常の先読み表示を重ね、4 サイクルで通常の流れへ戻します。分解中はスローモーションを維持し、再充填に合わせて徐々に通常速度へ戻します。重なる間は最大 48 行です。表示カーソルだけの演出で、プロセッサのサイクル、fetch / retire 時刻、占有数、ROB の状態は巻き戻しません。

フラッシュの 0.8 サイクル前から滑らかに減速し、分解中は 0.27 倍で再生します。再充填が始まる 2.8 サイクル後から徐々に加速し、5.4 サイクル後に通常速度へ戻します。コード表示が通常に戻る 4 サイクル後で速度を急に切り替えません。フレーム間隔を小分けにして速度を積分するため、描画のフレームレートによって復帰の動きが大きく変わることも抑えます。複数の flush が重なれば遅い方を優先します。

巻き戻し途中の一時停止・逆向きシークも同じ表示になります。再生・演出・Auto orbit は、OS／ブラウザの「動きを減らす」設定にかかわらず ON で開始し、開始操作は不要です。右パネルの **Motion effects** を手動で OFF にすると、帯の逆流・分解・演出上の減速を抑え、`CODE SQUASH` の表示に留めます。この場合だけ、左上に演出が OFF であることと **Enable animation & play** ボタンを表示します。押すと、このページ内の演出を有効にして次の flush の直前から再生します。OS の設定は変更せず、ページを開き直すと再び ON で開始します。通常は Branch storm の **Jump to flush** ですぐ確認できます。

**gem5 の squash 時刻は推定値です。** 今回の CoreMark ログは O3PipeView の `retire:0` に squash の時刻がないため、命令 ID が連続する squash 群の最終観測時刻を使います。画面の flush 表示に `≈` を付けています。RSD の時刻は Kanata ログに従います。メモリ待ちは既存の推定処理による最短メモリ latency の超過区間です。

ROB の小さな光は allocation から終了までのエントリの占有を示し、同じ命令の移動する光点と同時に表示されます。完了時に ready になっても slot は解放せず、先頭の commit 時に head が進みます。commit の粒子は該当する先頭 slot から出ます。途中へのシークでも同じ head / tail / slot になるように allocation・retire・squash を時刻順に再生した snapshot を使用します。gem5 は確認できた物理容量 192 entries、RSD はサンプルから算出した表示用の容量を使います。

メモリからスケジューラへの通知は、非 squash 命令のメモリ待ち完了時刻に発生する **completion broadcast の演出**です。通知の着地点は行列の外周の wake-up bus です。producer が行列に残っていればその列へ、発行済みなら行列外のバスから依存する consumer 行へ通知します。待つ consumer がなければバス上で終わります。セルの解決は記録された ready 時刻に従い、通知の飛行が終わるまで issue を遅らせることはありません。通知の飛行に 1.2 サイクル分の表示時間を使いますが、元の issue 時刻やメモリ latency は変更しません。Miss & recover の Highlight には、最初の D-cache miss を起こしたロードの `Memory ready → scheduler` を含めています。

**COMMIT** は1 サイクルの commit 幅に対応したスロットを持ちます。gem5 は8枠、RSD は2枠です。そのサイクルに実際に commit した命令を終了時刻・順序に従って並べ、該当する枠を命令色で点灯します。未使用の枠は暗く、モジュールの下に `使用数 / 幅 THIS CYCLE` を表示します。squash 命令は含めません。ROB から出る粒子も同じ枠を通り、飛行時間は演出で元の終了時刻を変更しません。状態は `sonata.commitSlots` で確認できます。Top-down の分類名 `Retiring` は解析で使う名称を維持しています。

`COMMITTED / CYCLE` は直近 16 サイクル以内のサンプル範囲で計算する平均値です。サンプル終端で先頭へループします。

## 依存行列とレジスタ

表示名は **SCHEDULER** のまま、内部を正方形の **N × N dependency matrix** として描きます。行・列は同じスケジューラエントリの集合で、表記は `ROWS × COLS` です。セルはその行の consumer の命令色を使い、列が指す producer への依存を表します。発行済み producer への未解決依存は行列の左外側に保持し、架空の列を追加しません。表示用エントリ番号は安定して割り当てますが、実機の IQ 番号や容量の再現ではありません。

命令は各行の左で待ち、発行時にその行を右へ横切って出口へ抜けます。行列上の移動は小さな点と短い細線で示し、セルを覆う大きな光や横断する残光は出しません。右出口から外周を回った信号が対応列へ届くと、列全体が明るい細線として立ち上がり、縦の光が下から上へ走ります。発行演出は 0.9 サイクルで消え、依存セルは行の命令色を保ちます。slot がすでに別命令に再利用されているときは、その新しい列を光らせません。発行の演出だけで未完了の依存を解決済みにはしません。実際の ready 通知は左側の wake-up bus で受け、記録された時刻にセルが明るくなって消えます。左端から上辺を回って全列へ降りる常設の補助配線は外し、通知があるときだけ実際の依存先へ光を送ります。

- **RSD:** 元ログの `map: rN(pN)` 注釈から、実際の物理レジスタの producer / consumer を復元。埋め込んだ区間のロードはベースレジスタ１つがソースです。デコード途中で squash され map 注釈に到達しない命令には依存を補いません。
- **gem5 の既存2本:** ARM64 の逆アセンブルから scalar register RAW を推定し、`RAW ESTIMATE` と表示します。メモリアドレスの alias 依存は推測しません。
- **gem5 の追加2本:** 詳細ログからパーサーが取得した実際の依存辺を使い、`RECORDED` と表示します。x86 は macro-op の名称だけで分類せず、実際の micro-op を整数・ロード／ストア・分岐に振り分けます。

リネームは **Rn 本体に組み込んだ立体的な RAT 配列**として表示します。独立した表、物理番号の文字列、表への引き出し線はありません。1 論理レジスタを1本のバーとし、命令の流れる方向（X 軸）に直角な Z 軸方向へ向け、8本ずつの薄い段に並べています。32本を保ったまま奥行きを詰め、通常のフロントエンドに近い大きさにしています。小さな内部模様は物理番号のビットで、別のレジスタを表すものではありません。更新時は青い光が各バーの奥から手前へ走り、flush 復元時は赤い光が逆方向に走って旧対応を戻します。元の map イベントを使い、writeback だけでは更新を発生させません。未観測の行は暗く、RSD の r0 はバーに沿った固定の線です。Rn 上を通る命令の大きな光と残光は抑え、バーを隠さないようにしています。カメラの回転・拡大・Top view に追従する WebGL オブジェクトです。

**PHYSICAL REGISTERS** はスケジューラと演算パイプの間の独立したバンクです。RSD はログで観測できた **41 個**を固定のセルに並べています。実機の総容量の断定ではなく `41 OBSERVED` と表示します。値は論理側ではなく物理セルに保持し、4 bit ごとの値を 8 本のバーの明るさで表示します。直近の writeback はバンクの下に `WB pN ← 0x…` と表示。RAT が若い版へ切り替わっても、旧版の物理値は残ります。未観測の値は描きません。割り当て中は青い面、空きは暗い枠、状態未観測は薄い斜線で区別し、近くに `ALLOC / FREE / ?` の個数を表示します。旧版は RAT の対応から外れても保持し、解放時に初めて暗くなります。

RSD は明示されたステージ名に合わせ、**Is（issue の受け渡し）→ Rr（物理レジスタ読み出し）→ X（演算）→ Rw（書き戻し）** として描画します。ロードの Mt / Ma はメモリパイプに続きます。Rr では元ログのソース物理レジスタと読み出し経路が読み出す命令の色（整数＝ミント、メモリ＝アンバー、分岐＝紫）で明るくなり、値の読み出しを示す光が出力ポートへ進みます。キャッシュミス後の Is / Rr / X 再試行も同じ経路を通ります。元のサイクルはそのままで、汎用推定が Is を実行開始、Rr / X を ROB としていた対応だけをSonata 内で修正しています。Top-down は従来どおり既存解析器の結果を使います。

抽出は `scripts/scheduling-evidence.ts` にあります。ロードの再試行途中の値を採用せず、最後の Rw に対応する load 結果を使います。たとえば #4355 は 4013 cycle の `0x0` を 4014 cycle の writeback で反映します。flush の対応復元は若い命令から逆順で行い、物理レジスタ再利用後の古い writeback は反映しません。

gem5 の **Rename rush / x86 recovery** は `O3CPUAll` に実際に出力された整数レジスタの rename / restore / RegFile read / write を抽出します（`scripts/gem5-registers.ts`）。確認済みの **256 個の整数物理レジスタ**を固定配置し、観測した 64 bit 値を 8 byte の明るさで表します。読み出し時はソースのセルと経路がその命令色で光ります。Rn のバーは ARM64 では x0–x30 と SP_EL0 の32本、x86 では16個の整数アーキテクチャレジスタと16個の micro-op 一時レジスタ t0–t15 の計32本です。そのほかの内部整数番号が観測されれば行を追加します。対象は整数レジスタで、ログにない対応は推定で埋めません。具体的な番号や対応は `sonata.registers` で確認できます。読み出しパルスは実ログのアクセス時刻を起点に 0.7 サイクル表示し、元の命令時刻は変えません。

割り当てと解放は `scripts/register-allocation.ts` で履歴をまとめています。gem5 は rename、commit 時の旧版解放、squash 後の遅延 free-list 更新という実ログの記録を使います。RSD は map 注釈と commit / squash 時刻から解放を推定し、`RELEASE ≈` と表示します。いずれも単に RAT に参照がないことを理由に free にはしません。

既存の **Branch storm / Wide open** は O3PipeView のみで値の記録がないため、設定で確認できた 256 セルと `CONFIG ONLY / VALUES NOT LOGGED` を表示します。割り当て状態も未観測なので、256個すべてを `?` として表示します。Rn には ARM64 の32論理レジスタ分のバーを他のデモと同じ形状で常時表示し、`MAP NOT LOGGED` と明示します。論理レジスタの構成と実際の対応記録を分離し、対応が未観測のバーは暗く保ちます。観測していない値やリネームの変化は追加しません。

予測ミスした分岐自身は younger wrong-path と一緒に消しません。RSD の記録された分岐 #4454 は 4068 cycle の flush 後も ROB に残り、紫の印と `MISPREDICT #4454 / ROB · PRESERVED` が位置を示します。gem5 では squash 群の直前の命令が実行済みかつ生存している分岐の場合に限り、`RECOVERY BRANCH ≈` として候補を示します。原因の確定情報ではありません。実際に commit すると印も出口に追従して消えます。

描画検証時の画像は `artifacts/screenshots/` に保存します。状態は `sonata.dependencyMatrix`、`sonata.registers`、`sonata.registerReads`、`sonata.registerReadCells`、`sonata.registerAllocationCells`、`sonata.renameMapWords`、`sonata.issuePaths`、`sonata.registerLayout`、`sonata.recoveryBranches` で確認できます。検査では行とスケジューラ占有数の一致、共有 producer 列、RSD のロードのソース数、未知の依存を勝手に解決しないこと、writeback と flush 復元、分岐自身の ROB 残存も確認します。
