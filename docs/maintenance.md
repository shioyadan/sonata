# 継続開発のための判断と確認事項

初回公開前の検査と開発中の作業記録から、今後も必要な理由・制約・確認方法をまとめます。日付ごとの作業履歴や環境固有の記録はローカルの `work/WORKLOG.md` に残し、この文書には継続して使う情報を反映します。

## 単一 HTML と独立した再生モデル

本体HTMLを別のフォルダへ移動しても、ネットワークや開発環境に依存せず手元のFileを読み込み・再生できることを維持します。通常のビルドに必要なのは Node と同梱ソース・データだけです。TypeScript の型検査器とElectronは開発に使い、Konataの解析器は同梱して実行時のファイル読込みにも使います。ブラウザ用の `.cts` は Node 標準機能で変換します。型検査と型の除去は別の工程であり、通常ビルドに開発依存を持ち込みません。型付けでは未観測値の null / undefined を保持し、型を通すために実データを補完しないでください。

再生モデルを DOM / WebGL から分離することで、FIFO、依存関係、レジスタ、Top-down を描画と独立して検査できます。描画は同じモデルと記録時刻を参照します。ビルド検査では別ディレクトリで同じ HTML とgzip生トレースを生成します。描画検査ではHTML単体のFile読込みで外部要求を拒否し、サンプルは隔離したローカルHTTPの固定一覧からだけ取得します。

単一 HTML はアプリ本体の配布形式です。編集用のソースは配置・経路・GPU・画面表示などの責務に分け、起動と共通の再生・操作連携はアプリ内にまとめます。独立していない処理まで小さく分割すると、依存の受け渡しとファイル間の往復が増えます。一緒に変更する処理と状態の所有者を近くに置き、行数の上限だけで分割しません。ファイル数に固定上限は設けません。責務と変更のまとまりに応じて構成を見直します。改行を詰めて行数を減らさず、読みやすく整形した結果の行数増加だけで分割を決めません。カメラとシェーダーはそれぞれ独立したファイルへ分け、前者は入力と投影、後者はGLSL生成に限定します。境界・粒度・CSS の適用順は [ソースの構造](architecture.md) にまとめています。

未読込みの状態と準備済みの再生状態を分け、描画へは同期の `loadData` で準備した `Replay` を渡します。再読込みは準備の成功後に反映し、既存の scene / paths が参照するオブジェクトを置き換えません。フレームの集計も、部分的な空オブジェクトを仮置きせず、描画時に揃えてからDOMと診断APIで参照します。この初期化の区別のために、未観測の実データを既知の値へ変えてはいけません。

プレビューサーバーの配信対象も生成HTMLとカタログのgzip生トレースに限定します。URL の解釈に失敗した要求は 400 で拒否し、その後の正常な要求も処理できることを検査します。実装の境界とコマンドは [開発ガイド](development.md) を参照してください。

サンプルは小さなカタログだけを本体へ載せ、選んだデモが使う `samples/*.log.gz` を取得します。5デモで4本を共有し、Fileと同じWorker・Konata core・区間変換を通します。元ログの連続prefixを残すことでcycle起点、ID/RID、レジスタの初期状態、注釈の原文行番号を保ちます。配布ファイルはハッシュで固定し、旧 `data/traces.js` は移行・CPU回帰の比較対象だけにします。サンプルとFileで別々の解析規則を育てないでください。

詳細注釈は入力時のevent索引とチェックポイントから復元し、Top-downは有界な区間と標本から導出します。デモのカタログには名前・初期位置・見どころ・出典・確認済みCPU設定だけを置き、命令や解析結果の配列を入れません。導出済みの短いTraceは最大5件キャッシュしますが、全体storeと解析Workerはサンプルの解析後に解放します。取得失敗や取消しでは現在の表示を保ち、遅い応答が新しい選択やFileを上書きしないよう世代とAbortを併用します。`file://` ではサンプルを取得しません。

ISA・物理レジスタ数・語長・ROB容量などは、元configで確認したデモ設定と任意Fileの観測を区別します。既知の256物理レジスタを表示しても、その値やrename対応が未記録なら未知のままです。Top-downの分岐回復は支持例が足りない区間では断定せず、旧事前解析と集計値を揃えるために未観測の分類を持ち込まないでください。

FP／SIMDは分類器・累積構造profile・区間変換・再生モデルのkindを揃え、全体で観測済みの実行ユニットを区間移動で消さないようにします。待機列は全種類共通です。整数・分岐は表示先だけを統合し、branchのkind・色・回復分岐としての意味を維持します。管路は元の整数・分岐の本数を合算した表示用経路であり、実機の共有ポート構成の推定ではありません。変更時は同時発行・再試行・区間交換の位置、依存・issue/ready時刻を確認し、未観測FPレジスタを補わないでください。回帰は `npm test -- schedulers memory trace-file trace-window scene`、実File入力と3スタイルの表示は `npm run test:render -- --sections=import-layout` で確認できます。

## 記録・推定・演出の区別

トレースの時刻、依存関係、物理レジスタの観測値を表示の根拠にします。光の移動や形状は演出であり、命令の issue / commit / squash 時刻を変更する理由にはしません。未観測をゼロや空きで埋めず、未知として表示します。

- ROB は先頭で commit、末尾で allocation / squash する循環 FIFO。途中の完了で詰め直しません。
- RAT の対応が変わっても古い物理値は保持し、記録された回収または明示した推定規則で解放します。
- Top-down は現在から過去8サイクルを使い、将来の commit / squash を先取りしません。
- 予測ミスした分岐自身と、取り消された若い命令を区別します。

詳細な表示上の合意は [可視化の仕様](visualization.md) にまとめています。演出変更時にはこの仕様と実トレースを照合してください。

## 非同期の画面変化を検査する

Electron のネイティブウィンドウ、エミュレーションの viewport、media query の変更通知は、呼び出しが終わった瞬間にすべて反映されるとは限りません。モバイル検査後のデスクトップ復帰を固定の 400 ms 後に判定すると、viewport は戻っていてもサイドバーの DOM 移動がまだ終わっていない場合があります。

画面復帰は、制限時間内に実際の幅・高さ、compact 状態、サイドバーの配置、ダイアログの閉鎖を確認します。期限を超えた場合は最後に観測した状態をエラーへ含めます。`finally` には後始末を置き、成功時の検査で元の失敗を上書きしない構造にします。

読込み中のrange操作は、その時点のmin/maxに対する指定位置の割合で入力到着を待ちます。解析開始時のmaxによる下限だけでは、軸が広がった後のmouseDownを次のmouseMoveと誤認できます。ドラッグ中の軸・値・選択枠を固定する検査と、操作終了後の新しい軸への復帰は別に確認します。

期限の確認をポーリングの間だけに置くと、`executeJavaScript` などの応答待ちから戻らない場合に終了できません。条件確認や描画完了のPromiseにも同じ期限を適用し、失敗時の診断取得には短い追加期限を設けます。診断取得の例外で元の待機失敗を隠さず、期限後の結果で成功へ戻ったり次の確認を始めたりしないようにします。期限を超えてもブラウザ内の処理自体は取り消されないため、失敗後は次の検査へ進まず終了します。具体的な時間と引数は [開発ガイド](development.md#検証) を参照してください。

`captureAt` は診断値の更新に加えてGPU描画も実行します。依存行列・Top-downの全サイクル走査、ステージ間移動、スタイルの往復を連続して検査するときは、`sampleFrame` で1サンプルごとにブラウザへ制御を返します。採取した状態を保持して次のアニメーションフレームを待ち、採取とフレーム待機には合わせて10秒の期限を設けます。全時刻の検査と最後の画面確認を維持し、`gl.finish()` だけを同期的な走査へ加えて済ませないようにします。命令の投影影を含む連続描画はGPUプロセスの停止にもつながるため、描画品質や検査する時刻数を減らす前に、この処理の集中を確認してください。

`captureAt` は時刻をデモの表示範囲へ丸めます。抜粋開始前のステージも命令データには残るため、描画検査は実際の `sonata.cycle` が指定時刻と一致することを確認します。範囲外の経路はCPU検査で扱い、画面上の移動には範囲内の命令・時刻を使います。

再現時は、同じ操作順を保ったまま実行プロセスの利用CPU数を制限します。問題の走査だけを新しいページで実行すると、直前の操作による影響を再現できない場合があります。描画検査は毎回一時的なブラウザプロファイルを作り、以前のGPUキャッシュや設定に依存させません。GPU停止後はスタイル切り替えや描画が無効になるため、命令一覧が空というassertionだけで寸法計算の不具合と断定せず、直前のGPUエラーとcontext lossも調べます。

カメラの補間に使う時間は1フレーム75msまでなので、低速なソフトウェア描画では実時間よりゆっくり収束します。スタイル検査の俯瞰・材質確認・最大拡大と、ブラウザ操作検査のFit・最大拡大・MSAAなしの材質確認は、距離と角度の許容誤差を維持し、実際の収束を最大30秒待ちます。期限超過時はカメラの現在値・目標値と描画状態・ページの可視性を残します。キー入力や初期化など、カメラ収束以外の待機時間は延長しません。

低速描画の再現では、MSAAを無効にした実ページで4回ズームし、その間だけ`requestAnimationFrame`を1秒間隔へ遅らせます。半径誤差が0.01未満になるには約21フレーム必要なため、従来の10秒では未収束、新しい30秒以内には収束することを確認できます。遅延を解除した後も、MSAAが0、描画画素・命令・影が存在し、WebGLエラーがないことまで検査します。遅延の注入は検査側に限定します。

ヘッドレス環境の D-Bus メッセージと、テストを終了させた assertion は分けて調べます。Electron / SwiftShader の検証結果は、実機 Safari / Chrome や実 GPU の検証結果とは区別します。

## ブラウザ検査の追加方針

新しいページ内の検査は、文字列へ長いJavaScriptを埋め込む代わりに型付きの関数として書きます。`scripts/browser-test.cts` の評価・待機ヘルパーを使い、関数の外側にある変数へ暗黙に依存せず、必要な値を引数で渡します。共通化しても、待つ実状態、検査ごとの制限時間、失敗時の診断情報は維持します。

操作や障害を検査するときは、ユーザーが観測する結果まで確認します。キーボードは Electron の入力イベントを送り、配送完了と描画フレームを待ってから、操作対象と再生状態を検査します。入力欄やダイアログにフォーカスがある場合も含め、ページ全体のショートカットとの干渉を検出します。

描画障害は `WEBGL_lose_context` による実際の context loss と、ページ初期化時の WebGL 取得失敗を分けます。前者は復旧後の再生・描画画素、後者は案内とライセンスへのアクセスまで確認します。故障の注入は検査のブラウザ内に限定し、終了時に取り除きます。

追加ケースは既存の `npm run test:render` からも実行して CI に含めます。通常の検証に別リポジトリや元ログを要求しません。実行方法と各検査の範囲は [開発ガイド](development.md#検証) を参照してください。

## 外観を切り替える

Neon / Aluminum / Paper の切り替えは描画の変更に限定し、トレースを読み直して時計・カメラ・選択を初期化しない構成です。プリセット、形状・合成の役割、明るい面のdepth精度、接地影の限界は [外観の仕様](visual-styles.md) に記録しています。拡張時も未観測値の扱いと配置を全スタイルで照合します。

Aluminum / Paper は意味色・配置・固定部品・影を共用し、研磨筋と環境反射、紙の繊維・積層・折り筋を材質で描き分けます。明るいUIも `data-theme=light` を共用します。命令は正立して滑る金属パック・紙の折り箱で、CPU接地・本体描画・投影影で同じ面を使います。紙箱の半辺と金属パックの面はgeometryからGLSLへ共用し、形状を変えるときは支持点と姿勢キャッシュのキーも揃えます。細かい模様は面を切り替える前の位置微分をUVへ投影してLODを決め、縮小時のちらつきを抑えます。

採用する3スタイルに必要な処理へ絞り、使わなくなったプリセット・専用材質・命令形状・転がり軌道・屈折用の背景コピーは残しません。共通設定は残るスタイルが使うものだけを明示し、削除したスタイルを継承元にしません。検査も現在の形状を基準にし、状態保持・接地・影・描画画素の確認を維持します。

ピンチで回転しないことを検査するときは、カメラの目標角が不変であることを確認します。表示角は直前の操作から補間され続けるため、入力前後の浮動小数点数の完全一致だけでは誤検出します。

## 公開時に確認すること

通常の変更では、変更範囲に応じて [開発ガイドの検証](development.md#検証) を実行します。依存・デモ・ライセンス・公開構成を更新するときは、関連する次の項目も確認します。

| 対象 | 確認する内容 |
| --- | --- |
| Git の公開範囲 | 差分と追加ファイルに秘密情報、個人環境のパス、配布対象外の元ログ、生成物が混入していないか。初回公開や履歴を変更する場合は公開する履歴も対象にする |
| 依存 | `.nvmrc` とロックファイルで検証できるか。監査結果と、実際に配布される依存のライセンスを確認する |
| データと権利表示 | 出自、推定・未確認事項、原文の保持、配布 HTML の Licenses 表示 |
| 独立性 | 元ログや別リポジトリなしでビルドでき、本体HTML単体でFileを開け、サンプルだけを選択時に取得するか |
| 公開結果 | push したコミットの CI 成功、Pages ジョブ成功、公開 URL の応答とビルド内容の一致 |

CIの実行時間は、全デモの全時刻走査、複数スタイルで繰り返すモバイル検査、シーンを再初期化する障害復旧検査の合計で長くなります。通常のpushでは基本描画検査を使い、網羅的な検査はローカルと明示的な手動実行へ分けます。並列ジョブを増やすだけでは使用時間の合計を減らせません。区間ごとの経過秒を記録し、通常CIの時間上限を延ばして対応しないでください。

検査時間を減らす際は、同じ条件の反復と別の不具合を検出する検査を区別します。CPUでの接地計算とGPUバッファ・影の画素照合、モデルの因果性と実UIの早送りはそれぞれ残します。材質比較は同じ材質の全時刻をまとめて採取し、Neonへ戻した全時刻も再照合することで、時刻ごとのscene再構築を減らします。材質別の画面配置・描画は保持し、共通のタッチ・キーボード操作を材質ごとに繰り返しません。ステージ間移動の全経路・9時刻採取は `transfers` として材質から独立に実行します。

`npm test` と全描画の検査一覧は入口で明示し、別suiteをファイル末尾から暗黙に起動しません。大きな検査は状態モデル／再生時計／実サンプル、索引／Fileセッション／Worker要求など、一緒に変更する責務で分けます。短いテストまで細分化する必要はありません。対象を絞った実行と全範囲の成功を区別し、同じ環境の実測で時間の変化を確認します。全体のCPUテストが軽い場合は、境界条件や大きな合成fixtureを時間短縮のために削りません。


ローカルの検査成功、GitHub 上の CI 成功、サイト公開成功はそれぞれ別に記録します。 基本描画と全描画のどちらを実行したかも記録します。Pages は `verify` が失敗すると公開をスキップする構成です。公開手順は [ライブデモの公開](development.md#ライブデモの公開) を参照してください。

## 命令の描画負荷

描画の見た目が原因に見えても、CPU側の姿勢・接地計算を先に切り分けます。接地する全命令に5区間の軌跡を付けると、過去位置の接地・ステージ間移動も毎フレーム調べ直します。待機中の本体を再利用できても、動く命令の過去位置にはその効果が及びません。このためAluminum / Paperの詳細な軌跡は選択中の命令だけに限定し、本体・材質・影の品質を維持します。

性能比較には同じデモ・時刻列・カメラ・描画解像度を使い、初期化直後を除外して変更前後を交互に測ります。停止中の再描画だけでは通常再生の負荷を判断できません。GPU完了待ちを含む測定とCPUの処理別測定を区別し、SwiftShaderの数値を実GPUのフレームレートとして報告しないでください。

## ロード／ストアの表示時間

- メモリ命令を一つの固定長 pipe に正規化しない。短い STORE と長い LOAD の速度差が過大になるため、経路を分け、正常アクセスの最短時間に比例した長さと超過分の静止待機を使う。RSD の Is / Rr / X 再試行と completion は保持する。
- 分類は `src/memory.cts` を抽出器と再生側で共有する。`sb` の前方一致では ARM `sbfm` まで STORE になるため、短い命令名には完全一致を使う。
- `storeCompletions` は optional な独立記録。既存の短い実行時間や retire から推測せず、gem5 の `Store Tick` を fetch tick / cycle の対応で校正する。0、欠落、squash、未retire、排他的 store / RMW は通常ストアの完了値にしない。
- STORE のアクセス後の待機は既存のROBセルへ置く。RSDの3970サイクルでは6命令が同時に待ち、その後に再発行される。管路で処理中と見えないよう、最短時間の通過後は `rob` 区間にし、記録された Is / Rr / X で再び実行へ戻す。待機中は完了時刻までreadyにせず、ROBの再割当や新たな表示スロットを作らない。実行開始が抜粋外でも、既存の待機をROBへ移し、レジスタ読み出しを補完しない。
- RSDの長いRwと後続のIs / Rr / Xから再実行を確認できるが、待機時間だけで原因を判定しない。03のSTORE #4318は、ミスしたLOAD #4315のa2に依存する。STORE自身の書込み応答待ちとは断定せず、物理的な待機場所も推測しない。ROBへ置くのは表示上の整理で、元の時刻・依存・commit / squashは変えない。
- `scripts/check-memory.cjs` は速度、ROB内の静止・未完了・スロット保持、再試行、途中終了、配置、時刻保持を検査する。`check-store-evidence.cjs` は実parserを通した小さなfixtureで校正と未観測を検査する。描画検査の `check-memory-render.cjs` はROB内の同時待機、再実行・ROB復帰、コミット前後・記録された完了・逆シークで命令詳細と描画を確認する。

## 任意トレースのメモリ境界

大きなFileを全文文字列にせず、KonataのPagedOpStoreに保持します。Sonataの描画状態は有界な区間だけにし、全命令の再生配列や未完成Opの反復転送を追加しません。ファイル交換・取消でWorker/storeを解放します。区間の左境界を跨ぐ長い命令とEOF未完了を落とさず、同梱デモ専用のCPU設定・レジスタ推定を任意ログへ適用しません。固定Coreの更新と上限は[読込みの資料](trace-import.md)を参照してください。

Workerへ移すだけでは、読込み完了前に使えるとは限りません。解析Promiseの後ろへ区間要求を並べず、途中で公開されたstoreから選択区間を取得します。進捗は範囲と件数の更新に使い、画面の再構築を毎回行いません。途中表示は未受信の命令があることを示し、完了時の更新でも時刻・再生状態を保持します。検査では実Fileの後半を止め、EOF前に表示・再生・区間移動・取消ができることを確認します。

任意ログの検査は「開けた」「座標が有限」だけで完了としません。短い区間に順序逆転がないだけで既知のスケジューラを前段に変えないこと、RSDのIs/Rr/X/Mt/Ma/Rwと再実行、gem5の連続squash群が区間の境界を跨ぐ場合のROBを検査します。生の時刻と表示上の推定squash時刻を別に保持します。

巨大トレースの探索UIでは、表示窓の末尾をファイル末尾と混同しません。先読みは次の1窓だけとし、Workerの待ち窓も最新1件へ集約します。区間移動は再生状態を保ち、詳細の時刻指定・検索結果の選択では停止します。非同期応答から再生を再開させず、待機中の手動停止を尊重します。手動移動で古い継続応答を失効させる一方、EOF時の同一区間更新は最新の位置を読んで適用します。進捗通知でbookmarkの入力DOMを作り直さず、編集中のフォーカスと文字を保ちます。全体活動・検索も有界にし、観測した命令寿命からcache missやstallの原因を断定しません。仕様・上限・保存方法は[読込みの資料](trace-import.md)にまとめています。

読込み中に伸びる全体時間軸は、ドラッグ開始時の縮尺を操作終了まで保ちます。透明なrangeの値だけでなく、利用者に見える選択枠も入力に追従させます。Workerの古い区間取得を取り消してもParserは継続し、EOF時の更新と再生継続を失効させたままにしません。走査のyieldは取消応答と完了速度の両方を実測します。短い処理を命令数だけで細切れにすると、Parserの割込みが重なって取得完了が遅くなる場合があります。

空白の自動早送りは、生存中の命令がないと確認できた区間だけに適用します。変化の少ない長い待機と空白を区別し、未完了や観測済みのstore書込み待ちを保護します。未確定の読み込み範囲や集約binだけから無活動を断定せず、次fetchの前と完了演出の後に余裕を残します。自動移動には手動操作から取り消せる要求IDを使い、短い窓を高速で跨いでも早送り開始の猶予を毎窓リセットしません。

「固まる」という報告では、描画・UIの停止と長い静止待機を分けて確認します。fetchに100サイクル以上留まる実ログでは、再生時計が動いていても通常速度で約30秒静止して見えます。静止段の待機加速は空白スキップと別設定にし、加速中と倍率を明示します。ステージ遷移だけでなく段内で移動する実行パイプも保護し、記録された長さの変更や待機原因の推測を行いません。加速した時計は窓末端で止め、次窓の記録を適用してから続けます。先読みしたstoreの書込み完了を現在の待機と扱わず、最初のfetchより前にその保護をかけません。

待機加速は命令の有無ではなく、状態が変わらない区間を対象にします。メモリは表示準備後の通過と待機の分割を使い、元のMc・Is・Rrなどの観測境界も別に保護します。storeの完了待ちを最早fetchから最遅完了まで一括で禁止すると、長い待機が加速できず、過去へ戻った時にも閲覧履歴で挙動が変わります。待機と各完了を区間索引から取得し、途中の完了を飛ばさず、最後の書込みまでトレースの末尾に含めます。

構造推定と表示窓の選択を分けます。小区間から毎回構造を作り直すと、同じプロセッサでもパイプが消えたり最短レイテンシが変わったりします。全命令配列を追加する代わりに、保存時の有界な観測とID標本をWorkerに保持し、容量は推定値と明示します。区間境界では元の時刻に加え、同じ命令の表示位置と直前のcommit/squash演出も検査します。流入文字列の24行を窓の末尾でも保ち、演出時計を止めたcanvas画素を比較します。文字列の先読みのために将来の終了結果や全ステージを描画へ追加しません。固定シーンの再利用キーに窓ごとの転送ピークを含めず、形状・材質・レジスタ表示の違いとWebGL復旧は再構築へ反映します。

カメラの継続検査では目標位置・操作状態を厳密に比較し、補間中の現在値は微小な浮動小数点誤差を許容します。過去のpanからゼロへ近づく値は、画素が同一でも極小値のまま変化し続けます。位置の許容誤差だけで済ませず、演出時計を止めたcanvas画素の一致も確認します。

再生マーカーの位置は描画フレームごとに更新し、統計・命令詳細などのDOM更新の間隔とは分けます。CSSのtransitionで後追いさせると停止・逆シーク・空白スキップで現在時刻から遅れるため、同じ再生時計を直接使います。ROBのHEAD / TAILは記録上は離散値のままにし、表示専用の位置をイベント後に補間します。循環方向とsquashの巻き戻しを保ち、補間中の次イベント、逆シーク、窓境界でも位置が飛ばないことを確認します。

Kanataの部分再生を加速するときは、未retire命令がCoreのstoreにまだ入っていない点に注意します。最古の未retire fetchと現在cycleから確定境界を求め、表示窓取得時の境界を固定します。進捗が進んでも古い窓だけでは安全範囲を広げません。実Fileの後半を止め、EOF前の加速と未公開fetch手前での通常速度への復帰を検査します。

実ログで全体移動後に止まる場合は、非同期制御だけでなく表示容量の例外も確認します。小さいデモ用の上限は、1000命令を超えるROBで容易に不足します。上限を増やすときは固定半径での間隔、基板・配線・Fit、区間をまたぐ予約席を併せて検査します。Onikiriの待機名を汎用の段階順序だけで推定すると再試行待ちを実行と誤認するため、既知のダンパー規則を名前群で限定して適用します。

メモリの`memory-wait`には記録された待機と、表示のために推定した待機が混在します。ノード名だけで最短アクセスの終端を決めると、既存デモのLOAD最短値が3から1へ縮むことがあります。Onikiriの`Xlm / Xlu`は記録されたミス待ちとして開始を保護し、`Cm / Rw`などの既存の推定待機はアクセス全体から求める従来の基準を維持します。両方の最短値と管路の終了時刻をCPU回帰で区別します。
