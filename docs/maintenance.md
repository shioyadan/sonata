# 継続開発のための判断と確認事項

初回公開前の検査と開発中の作業記録から、今後も必要な理由・制約・確認方法をまとめます。日付ごとの作業履歴や環境固有の記録はローカルの `work/WORKLOG.md` に残し、この文書には継続して使う情報を反映します。

## 単一 HTML と独立した再生モデル

配布物を別のフォルダへ移動しても、ネットワークや開発環境に依存せず再生できることを維持します。通常のビルドに必要なのは Node と同梱ソース・データだけです。TypeScript の型検査器、Electron、Konata の解析器は開発・抽出に使います。ブラウザ用の `.cts` は Node 標準機能で変換します。型検査と型の除去は別の工程であり、通常ビルドに開発依存を持ち込みません。型付けでは未観測値の null / undefined を保持し、型を通すために実データを補完しないでください。

再生モデルを DOM / WebGL から分離することで、FIFO、依存関係、レジスタ、Top-down を描画と独立して検査できます。描画は同じモデルと記録時刻を参照します。ビルド検査では別ディレクトリで同じ HTML を生成し、描画検査では HTML だけをコピーして外部リソース要求を拒否します。

単一 HTML は配布形式です。編集用のソースは配置・経路・GPU・画面表示などの責務に分け、起動と共通の再生・操作連携はアプリ内にまとめます。独立していない処理まで小さく分割すると、依存の受け渡しとファイル間の往復が増えます。一緒に変更する処理と状態の所有者を近くに置き、行数の上限だけで分割しません。ファイル数に固定上限は設けません。責務と変更のまとまりに応じて構成を見直します。改行を詰めて行数を減らさず、読みやすく整形した結果の行数増加だけで分割を決めません。カメラとシェーダーはそれぞれ独立したファイルへ分け、前者は入力と投影、後者はGLSL生成に限定します。境界・粒度・CSS の適用順は [ソースの構造](architecture.md) にまとめています。

未読込みの状態と準備済みの再生状態を分け、描画へは `loadTrace` が返した `Replay` を渡します。再読込みは準備の成功後に反映し、既存の scene / paths が参照するオブジェクトを置き換えません。フレームの集計も、部分的な空オブジェクトを仮置きせず、描画時に揃えてからDOMと診断APIで参照します。この初期化の区別のために、未観測の実データを既知の値へ変えてはいけません。

プレビューサーバーの配信対象も生成 HTML に限定します。URL の解釈に失敗した要求は 400 で拒否し、その後の正常な要求も処理できることを検査します。実装の境界とコマンドは [開発ガイド](development.md) を参照してください。

## 記録・推定・演出の区別

トレースの時刻、依存関係、物理レジスタの観測値を表示の根拠にします。光の移動や形状は演出であり、命令の issue / commit / squash 時刻を変更する理由にはしません。未観測をゼロや空きで埋めず、未知として表示します。

- ROB は先頭で commit、末尾で allocation / squash する循環 FIFO。途中の完了で詰め直しません。
- RAT の対応が変わっても古い物理値は保持し、記録された回収または明示した推定規則で解放します。
- Top-down は現在から過去8サイクルを使い、将来の commit / squash を先取りしません。
- 予測ミスした分岐自身と、取り消された若い命令を区別します。

詳細な表示上の合意は [可視化の仕様](visualization.md) にまとめています。演出変更時にはこの仕様と実トレースを照合してください。

## デモの出自と権利表示

ログの名前だけでワークロードやシミュレータの版を断定しません。RSD の `mshr.log` は、ログ全体の108種類の PC と命令を実行ファイルに照合して `Asm/IntRegImm` テストと特定しました。同梱区間は `_load` の起動処理です。照合できたソースのリビジョンと、ログ実行時の正確な版・設定は別の情報です。

## 非同期の画面変化を検査する

Electron のネイティブウィンドウ、エミュレーションの viewport、media query の変更通知は、呼び出しが終わった瞬間にすべて反映されるとは限りません。モバイル検査後のデスクトップ復帰を固定の 400 ms 後に判定すると、viewport は戻っていてもサイドバーの DOM 移動がまだ終わっていない場合があります。

画面復帰は、制限時間内に実際の幅・高さ、compact 状態、サイドバーの配置、ダイアログの閉鎖を確認します。期限を超えた場合は最後に観測した状態をエラーへ含めます。`finally` には後始末を置き、成功時の検査で元の失敗を上書きしない構造にします。

期限の確認をポーリングの間だけに置くと、`executeJavaScript` などの応答待ちから戻らない場合に終了できません。条件確認や描画完了のPromiseにも同じ期限を適用し、失敗時の診断取得には短い追加期限を設けます。診断取得の例外で元の待機失敗を隠さず、期限後の結果で成功へ戻ったり次の確認を始めたりしないようにします。期限を超えてもブラウザ内の処理自体は取り消されないため、失敗後は次の検査へ進まず終了します。具体的な時間と引数は [開発ガイド](development.md#検証) を参照してください。

`captureAt` は診断値の更新に加えてGPU描画も実行します。依存行列・Top-downの全サイクル走査、ステージ間移動、スタイルの往復を連続して検査するときは、`sampleFrame` で1サンプルごとにブラウザへ制御を返します。採取した状態を保持して次のアニメーションフレームを待ち、採取とフレーム待機には合わせて10秒の期限を設けます。全時刻の検査と最後の画面確認を維持し、`gl.finish()` だけを同期的な走査へ加えて済ませないようにします。命令の投影影を含む連続描画はGPUプロセスの停止にもつながるため、描画品質や検査する時刻数を減らす前に、この処理の集中を確認してください。

再現時は、同じ操作順を保ったまま実行プロセスの利用CPU数を制限します。問題の走査だけを新しいページで実行すると、直前の操作による影響を再現できない場合があります。描画検査は毎回一時的なブラウザプロファイルを作り、以前のGPUキャッシュや設定に依存させません。GPU停止後はスタイル切り替えや描画が無効になるため、命令一覧が空というassertionだけで寸法計算の不具合と断定せず、直前のGPUエラーとcontext lossも調べます。

カメラの補間に使う時間は1フレーム75msまでなので、低速なソフトウェア描画では実時間よりゆっくり収束します。スタイル検査の俯瞰・材質確認・最大拡大は距離と角度の許容誤差を維持し、実際の収束を最大30秒待ちます。期限超過時はカメラの現在値・目標値と描画状態を残します。描画フレームを600ms間隔に遅らせると、材質確認の収束が従来の10秒待機を超えるケースを再現できます。

ヘッドレス環境の D-Bus メッセージと、テストを終了させた assertion は分けて調べます。Electron / SwiftShader の検証結果は、実機 Safari / Chrome や実 GPU の検証結果とは区別します。

## ブラウザ検査の追加方針

新しいページ内の検査は、文字列へ長いJavaScriptを埋め込む代わりに型付きの関数として書きます。`scripts/browser-test.cts` の評価・待機ヘルパーを使い、関数の外側にある変数へ暗黙に依存せず、必要な値を引数で渡します。共通化しても、待つ実状態、検査ごとの制限時間、失敗時の診断情報は維持します。

操作や障害を検査するときは、ユーザーが観測する結果まで確認します。キーボードは Electron の入力イベントを送り、配送完了と描画フレームを待ってから、操作対象と再生状態を検査します。入力欄やダイアログにフォーカスがある場合も含め、ページ全体のショートカットとの干渉を検出します。

描画障害は `WEBGL_lose_context` による実際の context loss と、ページ初期化時の WebGL 取得失敗を分けます。前者は復旧後の再生・描画画素、後者は案内とライセンスへのアクセスまで確認します。故障の注入は検査のブラウザ内に限定し、終了時に取り除きます。

追加ケースは既存の `npm run test:render` からも実行して CI に含めます。通常の検証に別リポジトリや元ログを要求しません。実行方法と各検査の範囲は [開発ガイド](development.md#検証) を参照してください。

## 外観を切り替える

Neon / Paper の切り替えは描画の変更に限定し、トレースを読み直して時計・カメラ・選択を初期化しない構成です。プリセット、形状・合成の役割、明るい面のdepth精度、接地影の限界は [外観の仕様](visual-styles.md) に記録しています。拡張時も未観測値の扱いと配置を全スタイルで照合します。

Paper は紙の繊維・積層・折り筋を材質で描き分け、明るいUIには `data-theme=light` を使います。命令は正立して滑る紙の折り箱で、CPU接地・本体描画・投影影で同じ面を使います。紙箱の半辺はgeometryからGLSLへ共用し、支持点と描画する面の寸法を揃えます。細かい模様は面を切り替える前の位置微分をUVへ投影してLODを決め、縮小時のちらつきを抑えます。

採用する2スタイルに必要な処理へ絞り、使わなくなったプリセット・専用材質・命令形状・転がり軌道・屈折用の背景コピーは残しません。共通設定は残るスタイルが使うものだけを明示し、削除したスタイルを継承元にしません。検査も現在の形状を基準にし、状態保持・接地・影・描画画素の確認を維持します。

ピンチで回転しないことを検査するときは、カメラの目標角が不変であることを確認します。表示角は直前の操作から補間され続けるため、入力前後の浮動小数点数の完全一致だけでは誤検出します。

## 公開時に確認すること

通常の変更では、変更範囲に応じて [開発ガイドの検証](development.md#検証) を実行します。依存・デモ・ライセンス・公開構成を更新するときは、関連する次の項目も確認します。

| 対象 | 確認する内容 |
| --- | --- |
| Git の公開範囲 | 差分と追加ファイルに秘密情報、個人環境のパス、元ログ、生成物が混入していないか。初回公開や履歴を変更する場合は公開する履歴も対象にする |
| 依存 | `.nvmrc` とロックファイルで検証できるか。監査結果と、実際に配布される依存のライセンスを確認する |
| データと権利表示 | 出自、推定・未確認事項、原文の保持、配布 HTML の Licenses 表示 |
| 独立性 | 元ログや別リポジトリなしでビルドでき、単一 HTML が外部要求なしで動くか |
| 公開結果 | push したコミットの CI 成功、Pages ジョブ成功、公開 URL の応答とビルド内容の一致 |

ローカルの検査成功、GitHub 上の CI 成功、サイト公開成功はそれぞれ別に記録します。Pages は `verify` が失敗すると公開をスキップする構成です。公開手順は [ライブデモの公開](development.md#ライブデモの公開) を参照してください。

## 命令の描画負荷

描画の見た目が原因に見えても、CPU側の姿勢・接地計算を先に切り分けます。接地する全命令に5区間の軌跡を付けると、過去位置の接地・ステージ間移動も毎フレーム調べ直します。待機中の本体を再利用できても、動く命令の過去位置にはその効果が及びません。このためPaperの詳細な軌跡は選択中の命令だけに限定し、本体・材質・影の品質を維持します。

性能比較には同じデモ・時刻列・カメラ・描画解像度を使い、初期化直後を除外して変更前後を交互に測ります。停止中の再描画だけでは通常再生の負荷を判断できません。GPU完了待ちを含む測定とCPUの処理別測定を区別し、SwiftShaderの数値を実GPUのフレームレートとして報告しないでください。

## ロード／ストアの表示時間

- メモリ命令を一つの固定長 pipe に正規化しない。短い STORE と長い LOAD の速度差が過大になるため、経路を分け、正常アクセスの最短時間に比例した長さと超過分の静止待機を使う。RSD の Is / Rr / X 再試行と completion は保持する。
- 分類は `src/memory.cts` を抽出器と再生側で共有する。`sb` の前方一致では ARM `sbfm` まで STORE になるため、短い命令名には完全一致を使う。
- `storeCompletions` は optional な独立記録。既存の短い実行時間や retire から推測せず、gem5 の `Store Tick` を fetch tick / cycle の対応で校正する。0、欠落、squash、未retire、排他的 store / RMW は通常ストアの完了値にしない。
- STORE の実行待機は `exec-store` の `waiting` 区間とし、筐体内の出口へ配置する。RSD には6命令同時待機があるため1点へ重ねない。待機位置への移動で物理レジスタへ戻らず、管路の通過速度・長さを保つ。コミット後の記録は詳細表示へ置き、独立した台・輪・表示スロットを作らない。
- `scripts/check-memory.cjs` は速度、静止、再試行、途中終了、配置、時刻保持を検査する。`check-store-evidence.cjs` は実parserを通した小さなfixtureで校正と未観測を検査する。描画検査の `check-memory-render.cjs` はコミット前後・記録された完了・逆シークで命令詳細と ROB、STORE出口の同時待機を確認する。
